**Is your feature request related to a problem? Please describe.**
This could also be a bug, I'm not sure whether `includehidden=True` is intentionally not used in `tocdoc = self.env.get_and_resolve_doctree(...)`.

In our documentation we have a section that sums up its subdocuments using tables, like this:
```rst
Section
=======

Subsection 1
------------

.. list-table::

   * - :ref:`elt1`
      - Some description
   * - :ref:`elt2`
      - Another description

.. toctree::
   :hidden:

   doc1
   doc2

etc.
```
This works nicely with the HTML builders, but not with QtHelp. There, the `doc1` and `doc2` do not show up in the TOC outline of the Qt help viewer. This is because the `qthelp` builder calls
```
        tocdoc = self.env.get_and_resolve_doctree(self.config.master_doc, self,
                                                  prune_toctrees=False)
```
(https://github.com/sphinx-doc/sphinxcontrib-qthelp/blob/783caf58e9ba9cf0450746b7f65d4bc8229ccd8f/sphinxcontrib/qthelp/__init__.py#L97-L98)

If we would replace the table and the hidden toctree with a visible toctree, the documents would be listed in the TOC outline.

**Describe the solution you'd like**
Either pass `includehidden=True` in the call, or have a configuration option that allows setting this for specific sites.

Which is better depends on whether this is more a bug or a feature. I'm tending a bit to bug, but I'm quite unsure since I don't know whether omitting `includehidden=True` is intentional or not. (This part of the code never changed since the [initial commit](https://github.com/sphinx-doc/sphinx/commit/04348edceeff0e308fd1588ce0b76108e467c133).)

**Describe alternatives you've considered**
Using a non-hidden toctree is not really an alternative for us, since it looks much worse in the regular HTML build. Besides that, I've considered forking the qthelp builder locally; I'd prefer an upstream solution though.
