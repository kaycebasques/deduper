I create a theme that inherits from the user's theme and customizes `layout.html`. If the user's theme is one of [default](https://github.com/sphinx-doc/sphinx/tree/master/sphinx/themes/default), [nature](https://github.com/sphinx-doc/sphinx/tree/master/sphinx/themes/nature), [sphinxdoc](https://github.com/sphinx-doc/sphinx/tree/master/sphinx/themes/sphinxdoc), or [traditional](https://github.com/sphinx-doc/sphinx/tree/master/sphinx/themes/traditional), those don't have their own `layout.html`; they rely on the one in `basic` or `classic`.
- If my `layout.html` starts with 
```html
{% extends "!layout.html" %}
```
I get `RecursionError('maximum recursion depth exceeded')`.
- If my `layout.html` explicitly starts with 
```html
{% extends "sphinxdoc/layout.html" %}
```
I get `TemplateNotFound('sphinxdoc/layout.html')`. The same happens with `default`, `nature`, and `traditional`.

If the user's theme is any of the other builtin classes, then, e.g.,
- Explicitly extending that theme's layout
  ```html
  {% extends "pyramid/layout.html" %}
  ```
  is fine.
- I realize now that using an exclamation point
  ```html
  {% extends "!layout.html" %}
  ```
  still gives a recursion error. I guess this is what the [comment in Theming:Templating](https://www.sphinx-doc.org/en/master/development/theming.html#templating) is about?
  > When extending a template in the base theme with the same name, use the theme name as an explicit directory: {% extends "basic/layout.html" %}. From a user templates_path template, you can still use the “exclamation mark” syntax as described in the templating document.
