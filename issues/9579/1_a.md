**use case**
I'm using submodules in my sphinx documentation to reuse generic descriptions. Though in some descriptions you have variables that are different for each top-level project where they are included in.

Compiling now the generic code, I get a huge dump of Warnings that none of the variables are declared. In the generic build documentation I would like to hide the warnings such that I can better distinguish between intentionally made warnings and real warnings. Reason I do not want to declare them is to make sure the submodule pushes a warning for each undeclared variable when included in a new parent project to make the user aware he has to write these variables.

**Describe the solution you'd like**
Add the substitution function to the suppress option available in the .conf

**Describe alternatives you've considered**
I've tried defining variables at different levels that could then be overwritten from above but this also casts warning due to duplicate variable declarations.
