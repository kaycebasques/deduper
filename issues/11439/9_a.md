@picnixz This is somewhat of a less common syntax (and perhaps older if not legacy? Predating the current state of the [`typing`][1] module):

> `param2 (int, optional): description2`

Here optional doesn't express the `None` type as in `param2 (Optional[int]): description2` in [Python 3.10<][2] or as `param2 (int | None): description2` in [Python 3.10+][3]. Parameters with default values in a signature are implicitly *"optional"* (optional being plain English unrelated to the `None` type).

The Sphinx docs still have a few scattered examples of this kind of syntax ([for example here][4]) but where I think it's seen most is in the [numpydoc context][5]. I have to wonder if this syntax is still used or if it should be considered legacy altogether (and a poor practice at present, that's especially prone to add confusion for beginners), because reading through the PEPs and numpydoc I can't find a solid reference or need for it in 2024.
