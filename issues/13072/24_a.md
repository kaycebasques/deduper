I hope this is the right place to ask: with ``env.app`` going away, what's now the recommended way to initialize config-dependent domain data?

I'm trying to remove ``env.app`` usage from an extension, and I'm hitting a tricky problem in that I have a domain that needs the config. I'll give a simple mock example:

```
DEFAULT_CONF = {
    "brackets": "()",
    "separator": ";",
}

class MyDomain(Domain):
    name = "mydom"
    initial_data = {
        "conf": DEFAULT_CONF,
    }

    def __init__(self, env):
        super().__init__(env)
        self.data["conf"].update(env.app.config.some_conf_key)
```

Although the above code works today, going forward, I understand I connect to something like ``config-inited`` from within my extension's setup function instead. However the environment has not yet been configured yet at that stage... What's best practice to migrate the above code?
