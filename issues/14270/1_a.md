https://github.com/sphinx-doc/sphinx/blob/cc7c6f435ad37bb12264f8118c8461b230e6830c/sphinx/ext/napoleon/docstring.py#L361

which results in this if one turns warnings into errors:

> sphinx.deprecation.RemovedInSphinx11Warning: The mapping interface for autodoc options objects is deprecated, and will be removed in Sphinx 11. Use attribute access instead.

### How to Reproduce

Sadly I couldn’t figure this out. But it makes sense that it happens:

1. Autodoc’s dynamic loader emits the `autodoc-process-docstring` event and passes `_AutoDocumenterOptions`: https://github.com/sphinx-doc/sphinx/blob/cc7c6f435ad37bb12264f8118c8461b230e6830c/sphinx/ext/autodoc/_dynamic/_docstrings.py#L109-L128
2. Autosummary uses that object in a boolean context: https://github.com/sphinx-doc/sphinx/blob/cc7c6f435ad37bb12264f8118c8461b230e6830c/sphinx/ext/napoleon/docstring.py#L361
3. That object has no `__bool__` method, so its `__len__` method gets used as a fallback, which warns: https://github.com/sphinx-doc/sphinx/blob/cc7c6f435ad37bb12264f8118c8461b230e6830c/sphinx/ext/autodoc/_directive_options.py#L138-L144

And I think the fix is straightforward:

Add a `__bool__` method to `_AutoDocumenterOptions` so `if options` doesn’t warn.
