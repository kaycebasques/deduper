For some context, the upcoming Sphinx 8.3.0. indicates a couple of new changes for type aliases:

> Changelog
> [Release 8.3.0 (in development)][1]
>
> #10785: Autodoc: Allow type aliases defined in the project to be properly cross-referenced when used as type annotations. This makes it possible for objects documented as :py:data: to be hyperlinked in function signatures.
>
> #13508: Initial support for [PEP 695](https://peps.python.org/pep-0695/) type aliases. Patch by Martin Matouš, Jeremy Maitin-Shepard, and Adam Turner.

Before that there was a workaround for some cases documented here https://github.com/sphinx-doc/sphinx/issues/10785#issuecomment-1321100925 (can't believe it's been 3 years since I wrote that) but it's troublesome to get right and needs to be carefully maintained manually.

> I believe that we should use `py:obj`

Conceptually I'm not sure why a generalization of roles would help (shouldn't roles and types be as specific and narrow as possible?)! We've seen many devs in this repo reporting they go for `py:obj` whenever they're unwilling to make a distinction, but that will make for spaghetti code (you can't search de .rst code base based on roles) and there have been cases of the more general role not resolving everything correctly. I recall one case of a huge code base written with `py:obj` everywhere that used autosummary, when eventually a change in one of those declarations happened the error message became obscure because a more specific role hadn't been chosen...
