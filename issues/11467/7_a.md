Personally, I don't care. For most of my use cases of an enumeration, I would prefer having the enumeration member rather the value to be used, but it's because my enumeration classes are usually public. However, consider the following example:

```python

class _My123(IntEnum):
    not_a_two_nor_a_three = 1
    zwei = 2
    trois = 3

@dataclass
class Public:
    value = _My123.not_a_two_nor_a_three

    def use1(self):
       self.value = _My123.not_a_two_nor_a_three

    def use2(self):
       self.value = _My123.zwei

    def use3(self):
       self.value = _My123.trois
```

Fair enough, it's a bad and stupid example, but if we don't want expose the `_My123` enumeration class, we would have `_My123` being exposed visually because of the constructor dataclass but we would have `value = 1` by default, which would be much more explicit than `_My123.not_a_two_nor_a_three`. So I don't really know. It would make sense for non-literal enumeration values or for flag-like enumerations to use the enumeration member (because its name is usually more explicit than its value) but for constants with "private" names it may be more intuitive to have the value rather than an obscure name.
