There's an overarching issue here, because `:returns:` and `:yields:` aren't uniform in their presentation and the corresponding bugs have been reported before. For multiple values with types linking in the `:returns:` field see #9394 and for yield see #10982.

There's also a pragmatic reason why `:rtype:` has been kept on a separate line, that is if you have a long nominal type in the  `:rtype:` and a long description in `:returns:` there won't be much you can write into the usually narrow page width so keeping them separate, albeit the apparent format inconsistency, has been seen as acceptable.

A complementary issue to this, is that if the `:rtype:` is long you'll likely be using `@overload` soon which delegates some of the complexity to the signature above the callable, and should have more detailed documentation in the returns field as shows above in #9394.

I don't think that patching anything is the solution here before the ongoing rewrite of autodoc is settled.
