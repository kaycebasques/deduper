That first issue, #9394, is related but different: it's about the napolean extension, which allows Google/numpy docstrings rather than the usual RST docstrings. But RST is what Sphinx uses natively, so under the hood napolean translates other docstrings to that. So there are really are two separate bugs:

* This issue: Even in native RST, there's no way to specify multiple return types and descriptions.
* That other issue: When the napolean extension translates docstrings from Google/numpy format to RST format, it does not use the correct RST notation for multiple return types/descriptions. (Because there currently isn't one!)

The right way to proceed is to first fix this issue, and then that will allow the napolean issue to be fixed to make use of this new RST facility.

I don't know anything about the autodoc rewrite but I don't think it is a reason to delay fixing this issue. I'm suggesting changing (within the Python domain) the handler for the `:return:` directive to be the same as the already existing one for the `:exception:` directive. This is not really writing any new logic, just pointing an entry in a dict at a different already-existing class. If the autodoc rewrite means that this `PyGroupedField` class needs to change then that would need to happen anyway for `:exception:` to keep working, at which point `:return:` will pick up that change automatically.
