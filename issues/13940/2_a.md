Although the first quoted code comment seems to indicate something should be made better, the core issue is hard to avoid: we can not nest a breakable framed box inside another one. This issue exists the same with `tcolorbox`.  The current implementation decides to drop the unbreakable framing (or background color) so that the code-block embedded in an admonition (which also uses framing, and needs to allow pagebreaks) will not overflow the bottom of the page from being encapsulated in some minipage in order to be framed.

There is only one way I see to work around this in a general way, which is to actually to split the code-block at the LaTeX level into consecutive framed pieces, each one individually framed and glued one to the other with pagebreak allowed.

This is a rather massive effort which will have in our Sphinx context to handle also the case of long code lines which are handled by our mechanism to wrap them to not overflow horizontally, and thus occupy multiple lines. 

In summary the dropping of the frame for the inner code-block is a fall-back which gives a half-decent result avoiding approaches which will cause code-blocks to overflow the page bottom and partly disappear, and improving on this is estimated to require a significant amount of work. As far as I know from last time I checked, packages such as `tcolorbox` which are widely used by LaTeX users do not solve the similar issues in their contexts.  My info may be outdated.
