I'd note that there is also this kind of functionality in `SphinxTestApp`: 
https://github.com/sphinx-doc/sphinx/blob/3e29abf8de3f6f29aff18859b5eb88c8c79a1cbc/sphinx/testing/util.py#L89

but obviously this is not really exposed as a way for users to build projects.

I would also point you towards https://github.com/executablebooks/rst-to-myst/blob/6e51d18521eaa95d48d82f083fe81a13f8529485/rst_to_myst/namespace.py#L29, where I had to deal with these kind of problems with how to get sphinx to run as an API:

- docutils and sphinx load a number of global variables, like dictionaries of directives and roles. This is not great, especially for tings like asynchronous use, and I think me and @AA-Turner have discussed before about having the roles and directives passed directly to the parser

- sphinx dynamically monkey patches some things in docutils. Again not great, and really the changes should be upstreamed to docutils

Also yes, "overwhelmingly in favour of on-disk files", makes it difficult to use sphinx in any kind of `text -> output` type uses
