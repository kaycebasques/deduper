I am adding some info from [dvisvgm](https://dvisvgm.de) author:

> dvisvgm with option --page-hashes [...} creates file names with hash values in it which depend on the page contents. If several pages contain the same content, they get the same file name and it's only converted once. Also, when running dvisvgm again on a slightly changed file, the conversion of already existing SVG files is skipped because the page content hasn't changed.

But does Sphinx use a renewed tempdir each time ? It could be good to keep a copy of the used intermediate LaTeX file holding all math snippets; say one such LaTeX file per source document, in order to hand over hash creation and checking to dvisvgm. However we have to handle the problem of the depth, which is fixed at #6310 by adding it at end of each individual svg file. For multipage handling here is example output


which will have to be parsed to associate the depth to each svg file with already hashed filename.


Note: I initially used ``standalone`` package but then I encountered problems with the ``amsmath`` environments. I have not looked at a fix, as I realized using ``preview`` package works well. Indeed the ``testsvg.dvi`` used above was obtained from an original LaTeX source like this

```latex
\documentclass[12pt]{article}
\usepackage[utf8x]{inputenc}
\usepackage{amsmath}
\usepackage{amsthm}
\usepackage{amssymb}
\usepackage{amsfonts}
\usepackage{anyfontsize}
\usepackage{bm}
\pagestyle{empty}

\usepackage[active,tightpage]{preview}
\begin{document}
\begin{preview}
\begin{equation*}
E=mc^2    
\end{equation*}
\end{preview}
\begin{preview}
\begin{equation*}
x^n+y^n=z^n
\end{equation*}
\end{preview}
\end{document}
```

where the start of header is the one used currently by default by imgmath, but I think we can remove the utf8x.

This would turn ``preview.sty`` into a dependency of ``imgmath`` for SVG output. I think this is not blocking.
