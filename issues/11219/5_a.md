Nodes should have a unique name because of the visitor pattern used behind the scene. The visitor pattern as implemented by `docutils.nodes.NodeVisitor` checks the class name to get the correct dispatching method. Now, if we register by qualified name, this means that we need to also check by qualified name and then by normal name first in the visitor pattern. 

How can we know that `visit_module_my_node` is for `module.my_node` and not for a node named `module_my_node` ? Adding a node using `add_node` or any other interface should be semantically equivalent to write that node class *inside* the `docutils.nodes` file directly.

In Python, there is no real polymorphism like in C++ or in Java, so visitor patterns rely on dispatching by name. Technically, node visitors could be implemented using a single dispatch approach and polymorphism, but this is not a true polymorphism because we would 1) use `isinstance()` 2) need to sort which dispatcher to use in priority 3) be probably much less efficient than using Python reflectivity. 

> i'm not sure how trivial it is to change this behaviour. 

The change will be non-trivial and may result in breaking a lot of projects. Also, this would affect `docutils` because the XML tag name is by default set to the class name. With the qualified name approach, debugging becomes much more complex (again, how to distinguish between the XML element generated by `foo_bar` and `foo.bar` nodes, unless explicitly setting a different tag name?).

The application loads the extension before the test is instantiated. In your "failing" test, you are not using pytest, but are directly using your own extension. Since you are using poetry and are passing the `-W` option, the Sphinx application constructor has a `warningiserror=True` argument. 

During tests, the sphinx application being used is `SphinxTestApp` which *forcibly* sets `warningiserror` to False, whatever you do. Since extensions are loaded upon construction, the moment you put `app.warningiserror=True`, extensions are already loaded.

Even if it were using the normal one, the parameter of your test function `app` already exists, namely it has been constructed beforehand. Since `app.build()` does not load extensions, you will never get your warning as error even if you had set your `warningiserror` to true. You'll only get warning as errors if there are warnings during the building phase.
