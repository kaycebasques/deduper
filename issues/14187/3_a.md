One thing I can tell is that using `difflib.unified_diff` may be slow when there is a lot of output (depending on what you're matching, e.g., matching the debug messages as well) and it's more efficient to use the `diff` command directly. I encountered a diff in my current job that was 80 MB and difflib was very slow. I do not know if using `Differ.compare` would be more efficient though but using `diff -u2 --suppress-common-lines --speed-large-files` solved my issue.
