It seems to me that Sphinx internal hyperlink targets are designed to be resolvable across an entire project.

Additionally, because targets are declared and referenced using a simple label naming scheme, I think that it is by-design and intentional that no namespacing (either optional or explicit) is involved when declaring or resolving hyperlinks to targets.

A practical benefit of this is that a target can be cut-and-pasted from file A to file B -- with any arbitrary number of inbound hyperlinks within the project from documents C, D, E, ... -- while only requiring text editing (and therefore potential version-control conflict resolution) for files A and B.

I think this implies that declared Sphinx internal hyperlink target label names _do_ need to be unique within each distinct project, and so duplicates should be considered warnable.

The exception case of reducing log message severity for external hyperlink targets makes sense. Logging those (as opposed to suppressing any logging for them entirely) also seems valuable because if/when an externally-hyperlinked resource's location is updated, it is useful for editors to be aware when multiple outbound references to it exist from a project.
