The minimal reproducer in https://github.com/sphinx-doc/sphinx/issues/13383#issuecomment-2676337637 is actually not minimal and, because of a repeated fatal typo, misleading.

The minimal example would contain just 2 files establishing internal targets, e.g.
a.rst:
~~~
.. _duplicate:

This paragraph gets the "reference name" `duplicate`.
~~~
b.rst::
~~~
An inline internal target _`duplicate`.
~~~
The target duplication is:

a) no problem as long as only referenced with "native" rST syntax,
b) ambiguous when referenced with the Sphinx `:ref:` role.

The rST syntax element
~~~
`something <duplicate>`_
~~~
describes a "named hyperlink reference with embedded external target". 
It is equivalent to
~~~
something_

.. _something: duplicate
~~~
and links to the *URI reference* `duplicate`. Cf. [embedded URIs and aliases](https://docutils.sourceforge.io/docs/ref/rst/restructuredtext.html#embedded-uris-and-aliases).

It seems this was intended to be a "named hyperlink reference with embedded **alias**" (mind the trailing underlina after `duplicate`):
~~~
`something <duplicate_>`_
~~~
However, this would make `something` a duplicate target, too, so maybe it should have been an "anonymous hyperlink reference with embedded alias" (mind the double underscore at the end):
~~~
`something <duplicate_>`__
~~~
or just a simple use-case: 
~~~
duplicate_
~~~
Up to now, all variants demonstrate use case a) — resolvable hyperlinks without ambiguity because "native" internal rST links are limited to the document.

Whether this is "fair" use or should get a warnign should be discussed by the community.

The ambiguous use case b)  is a link to the duplicat target with
~~~
:ref:`duplicate`
~~~
