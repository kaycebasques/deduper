> I'm not sure if it is a bug, the reST spec says: _"within a document"_ but extension of the behavior by Sphinx (to make the links work cross-document if there aren't multiple targets) doesn't seem invalid... Maybe it can be considered an undocumented Sphinx feature [...]

It is documented:
> To support cross-referencing to arbitrary locations in any document, the standard reStructuredText labels are used. 
> --  [Cross Referencing Arbitrary Location](https://www.sphinx-doc.org/en/master/usage/referencing.html#cross-referencing-arbitrary-locations) 

but there is a caveat:
> For this to work label names must be **unique throughout the entire documentation.** 
> --  [Cross Referencing Arbitrary Location](https://www.sphinx-doc.org/en/master/usage/referencing.html#cross-referencing-arbitrary-locations) , emphasis by me.

To me, this means:
* For labels that are unique in the complete documentation, it is valid to use :ref:.
* For labels with a duplicate in the documentation project, using :ref: is an error that should be reported by Sphinx.¹
* Labels that are unique in one document  (page) may be referenced with rST syntax (`label_` or ```link text <label_>__```) in this document without ambiguity – also if there are equally named labels in other pages of the documentation project. IMO, this is a valid use case.

> [...] this begs the question: the "internal" in _"internal hyperlink targets"_ would the be internal to what? (Internal to the whole "docs" doesn't make much sense, or does it?!)

For Docutils, "internal hyperlinks" are cross links where the `<reference>` element uses a [refid](https://docutils.sourceforge.io/docs/ref/doctree.html#refid)  attribute while "external hyperlinks" are links where the `<reference>` element uses a [refuri](https://docutils.sourceforge.io/docs/ref/doctree.html#refuri) attribute. 

For Sphinx, we may distinguish 
"document internal" (refering to an id in the same document, 
"project internal" (refering to an id in any of the documents of the project), and
"external" (refering to an URI). 


¹In Docutils, there is one extemption that may also be sensible in Sphinx:
duplicate "external" targets refering to the same URI are tolerated (only reported as an INFO level message). 
https://docutils.sourceforge.io/docs/ref/rst/restructuredtext.html#implicit-hyperlink-targets
