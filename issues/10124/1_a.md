### Describe the bug

When a class C has a type annotation, it causes all type annotations of its parents to be ignored.

It also has the following effects on its children read after the autodoc of C: `more than one target found for cross-reference`, and may have the wrong target document

### How to Reproduce

Create a project structured like this:

* a `BaseClass` with a type annotation
* an `AlmostBaseClass` that inherits `BaseClass`, and has its own annotation on an unrelated attribute
* optionally, child classes which both inherit `AlmostBaseClass`

For example:

```py
==> conf.py <==
project = 'test'
copyright = '2022, test'
author = 'test'
extensions = [
    "sphinx.ext.autodoc",
    "sphinx.ext.extlinks",
]
templates_path = ['_templates']
exclude_patterns = ['_build', 'Thumbs.db', '.DS_Store']
html_theme = 'alabaster'
html_static_path = ['_static']
autodoc_default_flags = [
    "members",
    "undoc-members",
    "private-members",
    "special-members",
]
autodoc_member_order = "bysource"

==> dep1.py <==
class ClashingClass:
    """dep1 ClashingClass"""
    pass

==> dep2.py <==
class ClashingClass:
    """dep2 ClashingClass"""
    pass

==> testsphinx/__init__.py <==

==> testsphinx/base.py <==
from typing import Optional

from dep2 import ClashingClass

class BaseClass:
    foo: Optional[ClashingClass]

==> testsphinx/mod1.py <==
from .mod2 import AlmostBaseClass

class Class1(AlmostBaseClass):
    """this is Class1"""

==> testsphinx/mod2.py <==
from .base import BaseClass

class AlmostBaseClass(BaseClass):
    """this is AlmostBaseClass"""
    bar: str

==> testsphinx/mod3.py <==

from .mod2 import AlmostBaseClass

class Class3(AlmostBaseClass):
    """this is Class3"""

```

Then run `sphinx-apidoc -o apidoc . --maxdepth=3 --separate` and `make html`

Here is a tarball with the source and results when compile with Sphinx 4.4.0: [testsphinx.tar.gz](https://github.com/sphinx-doc/sphinx/files/7906473/testsphinx.tar.gz)


### Expected behavior

With my example:

* `AlmostBaseClass` should have the `foo` attribute documented (because it inherits `BaseClass`), but doesn't
* ditto with `Class1`
* `Class3` does have the `foo` attribute documented, but it targets `dep1.ClashingClass` instead of `dep2.ClashingClass`
