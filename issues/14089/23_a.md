Our project also needs the legacy interface since it uses the [sphinx-interrogatedb](https://github.com/panda3d/sphinx-interrogatedb) extension which subclasses the regular Documenter classes to source the members, docstrings, signatures etc. from a separate database file, which is generated by our Python binding generation tool, [interrogate](https://github.com/panda3d/interrogate).

This matters because the documented objects are compiled C++ extension modules: the live Python wrappers have no introspectable signatures or type information, so the interrogate database is the only source of truth. It's what lets [our documentation](https://github.com/panda3d/panda3d-docs) ([example page](https://docs.panda3d.org/1.10/python/reference/panda3d.core.AnalogNode#panda3d.core.AnalogNode)) provide a high-quality API reference for those modules, including overloads and C++ type info.

From a cursory look, the new event-based hooks lack a way to completely override member enumeration for a given type, supplying the signature from an external source, or a way to choose the emitted directive/domain per object (we generate both Python and C++ versions of the API reference), among possibly other limitations, so the legacy class-based API is currently the only way for us to do this.
