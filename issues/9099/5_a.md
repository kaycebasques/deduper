> I think a common pattern is a class that has another class as an attribute, which can have its own attributes. Therefore the nested class's attributes are accessible on the parent class by chaining dot notation e.g. `self.env.ref_context`.

Sure, in Python a nested class can be accessed as an attribute, but not all attributes are nested classes. I believe the intention of the ``py:attribute`` directive is to document attributes that are not nested classes.

> This is done with a simple structure of nested classes. The classes themselves are private and I want the implementation to be opaque to the user, but I want all the attributes to be visible. I don't think autodoc is smart enough for this use case, so at the moment I'm automatically generating this nested tree of `py:attribute::` based on the option structure.

This sounds like a case similar to the one in #8657. So I guess something like
```rst
.. class:: A

   .. class:: _B

      .. attribute:: b: int

   .. attribute:: a: _B
```
(modulo whatever Python conventions I might have broken), but where you don't want to show ``_B``?

I think it may be helpful to get a minimal case study of the thing to be documented to figure out how to handle it.

Note that in general, when you nest directives for the programming language domains, then you scope the inner in the outer, so
```rst
.. attribute:: a

   .. attribute:: a.b
```
would theoretically mean something like
```rst
.. attribute:: a
.. attribute:: a.a.b
```
Was that the intention?
