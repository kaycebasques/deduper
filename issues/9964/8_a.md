The utf8 support is on per default.

But there is a catch as "utf8 support" is in the sense of LaTeX. So for example most European languages are supported out of the box, but beyond that not much. And pdflatex fonts provide at most 256 glyphs per font...

Sphinx has some built-in mechanism for cyrillic and Greek, but you need to read the docs.

As another example I needed to add custom support to `pdflatex` engine for the Unicode characters arising in the output of the unix "tree" command that people sometimes want to use in their Sphinx documents. In that case the characters end up being emulated by horizontal and vertical segments which TeX knows how to do (there is font providing these, but not all people have this font installed per default by their linux distros together with latex).

In the more common case though one needs:
- to find a font which supports the characters
- to add to latex preamble instructions to load this font AND character-per-character instructions to inform LaTeX that such and such character has to be rendered via such or such font.


This process is painful enough to explain that naturally people will tend to prefer usage of a real Unicode engine (`xelatex` or `lualatex`). BUT, this does not solve auto-magically all problems because LaTeX *does not have a built-in mechanism of automatic fall-back fonts*. So again one needs to use a font with very wide Unicode  coverage (this is why Sphinx opted for FreeFont), but in case the document requires glyphs not covered in default font, the problems re-appear a bit like for `pdflatex`...
