Currently, the theme puts in-page header navigation in the primary sidebar to the left:

![image](https://user-images.githubusercontent.com/1839645/178230744-5581ca48-afcc-456a-9ad2-6af99147245b.png)

However, it has become standard across modern documentation engines to use a three-column layout and put the in-page navigation on the right. Some examples:

- [Docasaurus](https://docusaurus.io/docs#something-missing)
- [Material for mkdocs](https://squidfunk.github.io/mkdocs-material/creating-your-site/)
- [GitBook](https://docs.gitbook.com/)
- [MarkDoc](https://markdoc.io/docs/getting-started)

And within the Sphinx ecosystem:

- [Furo](https://pradyunsg.me/furo/customisation/)
- [Book theme](https://sphinx-book-theme.readthedocs.io/en/stable/content-blocks.html)
- [PyData theme](https://pydata-sphinx-theme.readthedocs.io/en/latest/user_guide/configuring.html)

I think that Sphinx's documentation would evoke a more modern theme UI if it similarly used a three-column layout, with the right-most column containing in-page navigation to headers.
