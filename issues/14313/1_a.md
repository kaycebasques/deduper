### Describe the bug

I'm trying to convert my `TypeAlias` statements to use the new `type` expression, but no matter what I try, Sphinx does not like it.

### How to Reproduce

Apologies for the lack of minimal reproducer, I struggled to make a smaller version of this.

https://github.com/torchgeo/torchgeo/pull/3278 is the PR where I'm trying to make the switch. We have statements of the form:
```python
Sample: TypeAlias = dict[str, Any]
```
Sphinx renders this in the docs as `dict[str, Any]`: https://torchgeo.readthedocs.io/en/stable/api/datasets/eurosat.html#torchgeo.datasets.EuroSAT.__getitem__

Now when I try:
```python
type Sample = dict[str, Any]
```
[Sphinx complains](https://app.readthedocs.org/projects/torchgeo/builds/31475627/) with:
```
WARNING: py:class reference target not found: torchgeo.datasets.utils.Sample [ref.class]
```
When I add `Sample` to `torchgeo.datasets.__init__.__all__` and add `.. autotype:: Sample`, [Sphinx again complains](https://app.readthedocs.org/projects/torchgeo/builds/31475275/) with the same error message. Finally, when I replace `autotype` with `autoclass`, [Sphinx complains](https://app.readthedocs.org/projects/torchgeo/builds/31475133/) with a different message:
```
WARNING: Failed to get a constructor signature for torchgeo.datasets.Sample: Sample is not a callable object
```
I'm curious if you can figure out what I'm doing wrong. Given that I can't easily find a minimal reproducer, I'm guessing this is user error.
