Thanks for the report. I tested the reproducer against current `master` (`e44a40e`, Sphinx `9.1.1+`) and compared it with Sphinx 8.1.3.

The primary issue no longer reproduces on `master`. A signature containing a default value of the form `<...>` is rendered correctly, and types such as `typing.Any` are linked through intersphinx. I confirmed the reported behavior in Sphinx 8.1.3, but it no longer occurs on current master.

The separate `__repr__` case still reproduces. A function with one parameter whose default value has the representation `0, y: ~typing.Any = 1` is rendered as if it had two parameters:

```text
compare(x: Any = 0, y: Any = 1)
```

Since the `__repr__` behavior is distinct from the original `<...>` parsing problem, please open a separate issue to track it. That way we can close this issue as resolved.
