Agreed.  However, 
* you will *always* need to document how to specify whether an admonition should be presented including or excluding the title.
* Some themes rely on the title to differentiate specific admonitions (cf. [admonitions](https://docutils.sourceforge.io/test/functional/expected/standalone_rst_html5.html#admonitions) in the Docutils test output).

> Such an approach needs to be documented per theme (listing whatever admonition CSS class names the theme supports).

The proposed workaround is based on the HTML that is generated for the specific admonitions. 
* It should work with all CSS themes that correctly style Docutils- or Sphinx-generated HTML.
* It is a generic workaround to style body elements with either existing or custom CSS rules.
* Re-purposing an admonition's styling rules always relies on the CSS theme to comply with my expectations (see the link above for an example how this may fail if the title is hidden).

Alternatives:
* A "magic" css-class value works with custom CSS or a convention for themes. 
  ~~~rst
  .. hint:: 
     The title is still available for screen-readers.
     :class: hide-title
  ~~~
  The "macic" css-class value also works with the generic admonition.
  ~~~rst
  .. admonition:: good example
     :class: hint hide-title
      
     A screen reader would know this is a "good example" admonition.
  ~~~

* Use an escaped whitespace as "dummy title".
  ~~~rst
  .. admonition:: \ 
     :class: hint
   
     This still relies on the HTML output using specific 
     CSS-class values for the admonition type.
  ~~~
