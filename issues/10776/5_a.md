The way the links are rendered is theme dependent, linking the types is a choice controlled by setting [`napoleon_preprocess_types`][1].

This report together with #10793 that you also posted are especially problematic because neither includes a [minimal reproducible example][2], just a link to a repo that's changed in the meanwhile and does not include in the post the necessary  code to show what's being described in prose. (Stack Overflow has a good guide on [MREs][4] and both your reports would have been closed&deleted there for not complying with the minimum requirements.)

You aren't supposed to write cross-references into the docstring info fields. That's has never been the case, what napoleon does require (part of the broader family of bugs grouped in issue 11991) is occasionally including the fully qualified name in the type [info field list][2] of the [docstring sections][3], or the rst signatures if you need to customize them.

**You should not write**, as you've proposed here (and in the other linked issue), a cross-reference into the field :

```py
def one_function(an_arg: int):
"""Description.

Args:
        an_arg(:py:class:`qualified.name.to.object`): Description.
"""
```

You should just write the fully qualified name used in the import:

```py
def one_function(an_arg: int):
"""Description.

Args:
        an_arg(qualified.name.to.object): Description.
"""
```

> several styles are used to represent the same concept

Cross-references and HTML links (that happen to be for types) aren't the same concept. That's a misconception. When you set `napoleon_preprocess_types` you're asking for links to be resolved for types in signature and docstring fields, you're not asking those to be converted to cross-reference declarations.
