**Is your feature request related to a problem? Please describe.**
There is no real problem, rather aesthetics.

**Describe the solution you'd like**
I would like to have a box around the Python types instead of a default HTML link. I like the following appearance:

![grafik](https://user-images.githubusercontent.com/5236165/185383575-0731fda4-8cf3-4c87-80d5-1c3538539158.png)

However, when I describe my keyword arguments, default HTML links are used:

![grafik](https://user-images.githubusercontent.com/5236165/185383923-c3e374bb-5dbd-42aa-9682-65663f324dc3.png)

I like the boxes more. What especially bugs me is that currently, several styles are used to represent the same concept. This is partly my fault because of the configuration I chose. When I tried to streamline the visual appearance, however, I realised that I have limited control over this. As this is about taste, I guess it is better to add another option to the config and leave it up to the maintainer of a documentation to choose between a pure html link and a pre-styled box.

**Describe alternatives you've considered**
While writing doc strings, I could use the [py obj role](https://www.sphinx-doc.org/en/master/usage/restructuredtext/domains.html#role-py-obj) whenever encountering these types and do this job manually. That is some manual work and I would prefer if there was an automated way to solve this.
