**Sphinx version:** 9.1.0 (also reproduced on 7.4.7 and 8.2.3)
**Python version:** 3.12.13
**OS:** Linux
**Theme:** sphinx-rtd-theme 3.1.0

## Description

When the Sphinx source root is set to a parent directory (e.g. a monorepo workspace root) and `root_doc` points to a subdirectory (`subdir/doc/index`), rendering any page whose file lives **outside** that subdirectory raises a `ThemeError` wrapping `KeyError: 'refuri'`.

## Steps to reproduce

Directory layout:
```
workspace/
├── conf.py          # root_doc = "docs/index", html_theme = "sphinx_rtd_theme"
├── docs/
│   └── index.rst    # toctree includes "../README" and "../../other-module/README"
├── README.md        # <-- rendering this page crashes
└── other-module/
    └── README.md    # <-- rendering this page also crashes
```

`conf.py`:
```python
root_doc = "docs/index"
html_theme = "sphinx_rtd_theme"
```

`docs/index.rst`:
```rst
.. toctree::

   ../README
   ../../other-module/README
```

Build command (source root is the workspace root, conf.py is in docs/):
```
sphinx-build -b html -c docs . _build/html
```

## Expected behavior

All pages render successfully regardless of where they sit relative to `conf.py`.

## Actual behavior

```
sphinx.errors.ThemeError: An error happened in rendering the page README.
Reason: KeyError('refuri')

  File ".../sphinx/environment/adapters/toctree.py", line 189, in _resolve_toctree
      if url_re.match(refnode['refuri']) is None:
                      ~~~~~~~^^^^^^^^^^
KeyError: 'refuri'
```

Full call chain:
```
sphinx_rtd_theme/layout.html:169  {%- set toctree = toctree(maxdepth=...) %}
sphinx/builders/html/__init__.py:955  global_toctree_for_doc(...)
sphinx/environment/adapters/toctree.py:189  if url_re.match(refnode['refuri']) is None:
```

## Root cause

In `_resolve_toctree` (~line 189), reference nodes built when resolving the global toctree from a page outside the root doc directory are missing the `refuri` attribute. The same applies to `anchorname` in `local_toctree_for_doc` (~line 64). Both sites use plain `node['key']` access instead of `node.get('key', '')`, which raises `KeyError` instead of falling back gracefully.

## Proposed fix

Four sites in `toctree.py`:

```python
# ~line 64 (local_toctree_for_doc)
- node['refuri'] = node['anchorname'] or '#'
+ node['refuri'] = node.get('anchorname', '') or '#'

# ~line 189-191 (_resolve_toctree)
- if url_re.match(refnode['refuri']) is None:
-     rel_uri = builder.get_relative_uri(docname, refnode['refuri'])
-     refnode['refuri'] = rel_uri + refnode['anchorname']
+ if url_re.match(refnode.get('refuri', '')) is None:
+     rel_uri = builder.get_relative_uri(docname, refnode.get('refuri', ''))
+     refnode['refuri'] = rel_uri + refnode.get('anchorname', '')
```

## Workaround

Apply the above substitutions to the installed `toctree.py` after `pip install`.

## Notes

The setup (workspace root as source root, `root_doc` pointing into a subdirectory) is a monorepo pattern for collecting READMEs from multiple locations without symlinks. It is valid Sphinx configuration per the documentation.
