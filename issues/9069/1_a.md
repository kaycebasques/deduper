**Describe the bug**
Sphinx fails to import & document a module that is itself imported in an `__init__.py` file. I'm at a loss as to understand why; on the face of it, there's nothing wrong with this import statement. If I comment out the import statement, Sphinx imports & documents the module perfectly. Why is this?

**To Reproduce**

1. Clone `git@github.com:JamesALeedham/lusid-python-tools.git` and checkout the `sphinx-bug-query` branch.
2. View the [copy of the docs hosted here](https://lusid-python-tools.readthedocs.io/en/sphinx-bug-query/_autosummary/lusidtools.logger.LusidLogger.html#module-lusidtools.logger.LusidLogger) and observe that the `lusidtools.logger.LusidLogger` class is not documented (ie. page is empty).
3. In the repo, edit `lusidtools/logger/__init__.py` and comment out the single import statement, ie. `# from lusidtools.logger.LusidLogger import LusidLogger`.
4. Follow the instructions in the [docs Readme](https://github.com/JamesALeedham/lusid-python-tools/tree/sphinx-bug-query/docs#readme) to rebuild and view the docs locally as HTML.

With the import statement in `__init__.py` commented out, Sphinx documents the `lusidtools.logger.LusidLogger` class perfectly. ([Here's an example of what this page then looks like](https://lusid-python-tools.readthedocs.io/en/latest/_autosummary/lusidtools.logger.LusidLogger.LusidLogger.html#lusidtools.logger.LusidLogger.LusidLogger)).

**Environment info**
- Sphinx version: 3.5.3
- Sphinx extensions:  `sphinx.ext.autosummary` with the brilliant `:recursive:` option
