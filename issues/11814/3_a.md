I investigated this a bit and can provide some info which is not far from being complete enough so that some PR can be done, but there are some loose ends perhaps with non-English languages (untested).

- first of all, we do have in our Latexmk config a line for glossary https://github.com/sphinx-doc/sphinx/blob/35965903177c6ed9a6afb62ccd33243a746a3fc0/sphinx/texinputs/latexmkrc_t#L29-L32
- ... but it is inadequate as ``gglo.ist`` is actually some file using LaTeX commands which are not part of the LaTeX itself but of the ``doc`` package used by LaTeX programmers.  Indeed this  ``gglo.ist`` is to support the creation of "change logs", via the `\changes` macro inside `.dtx` files.
- besides ``makeglo`` is a misnomer it should have been ``makegls`` or ``glo2gls``,
- many decades ago, LaTeX was created and contained a `\glossary` command which was documented in Lamport book; but this command was not usable without never documented extra things (such as the ``gglo.ist``) and furthermore, in fact, never really support creation of glossaries, but rather of variants of indices.
- I have investigated (quickly) various packages, including ``nomencl`` but all online advices point to using ``glossaries`` LaTeX package.
- This is indeed a potent package, but designed to be used by a human.
- It is a rather humongous package, and even its so-pretending-to-be "short" introduction ``glossariesbegin.pdf`` is too big (57 pages, most of it we will never be able to use at Sphinx).
- The ``glossaries`` packages offers to be used with ``xindy`` if desired but in my short investigation I did not see how to fuse it with own Sphinx support which allows Cyrillic in indices event if document is otherwise Latin.  But roughly speaking for most Sphinx use cases that should work.
- Apart from the ``gglo.ist`` thing, which is easily fixed by replacing the Latexmk rule to employ the ``makeglossaries`` Perl script provided by ``glossaries``  package, the most important thing is that inside the LaTeX file, it is mandatory that the description of the glossary term is done prior to the first use of that term in the document.  We can not delay to after having used everywhere `\gls{some term}` mark-up the location of the term definition.  It has to be encountered in the LaTeX file as a `\newglossaryentry` before first use of `\gls`. EDIT: to be clear: the *definition in the LaTeX file* must be first, the *definition in PDF output*  will be located wherever ``\printglossaries``  has been inserted in the LaTeX mark-up and this can be at start of document if desired
- Last remark there is also `\Gls` which will try to uppercase initial, but this requires additional package IIRC, and a recent LaTeX if if it is to work well with Unicode characters.
