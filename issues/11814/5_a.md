The feature is relatively straightforward to implement on our side:
- modify `latex.tex_t` template to include in preamble `\usepackage[toc]{glossaries}\makeglossary`and at end of document body `\printglossaries`.  Also pass `xindy` option to `glossaries` if our `latex_use_xindy` is True
- modify the glossary directive so that it creates a file with one `\newglossaryentry` for each defined term, rather than using a LaTeX description list.  This file should probably be named `<master_doc>_glo.sty` with `sty` extension to avoid confusing our Makefile.
- also let the LaTeX preamble do  `\usepackage{}` on the sty file defined in previous item; this avoids to clobber the preamble with the entries definitions; in brief the contents of the glossary directive will be interpreted in a new way.  Notice that this means now we can not multiple glossary directives producing multiple glossaires at various places of PDF.  Only one global glossary which will coalesce all glossary directives contents.  Probably it is possible to maintain multiple ones, but then find someone to read the 712 pages of documentation of glossaries package, and this is only the main PDF of multiple ones of the documentation...
- modify the LaTeX writer to use `\gls` macro to support the `:term:` role in place of currently the architecture based on added hyperref labels inside the glossary definitions and usage of `\hyperref` at place of term use in document.  This means though we will have to think how to tell glossaries package to use our `\sphinxtermref` mark-up (currently something such as `\sphinxtermref{\DUrole{xref,std,std-term}{AK}` in your "AK" example.), 
- do the modififcations in our `latexmkrc_t` (and Japanese variant)  into the added Latexmk custom `glo --> gls` to let it use `makeglossaries`. Some Windows knowledgeable people should also extend the `/texinputs_win/Makefile_t` which does not use Latexmk and has kept a very inefficient way to produce the PDF ; I don't use Windows but see there is a `make.bat_t` in `/texinputs` which is equivalent to the unixen Makefile template there, and those two things will need no change, as all changes will be in `latexmkrc_t`.  I have completely forgotten what for a Windows user trigger use of the (very old) Makefile from our `/texinputs_win` or rather the seemingly fine `make.bat` from our `/texinputs`.
- the `latexmkrc_t` changes will cover both the `xindy` and the `makeindex` branches
- notice that  `makeglossaries`, like `latexmk`n is a Perl script; but one can make do without `makeglossaries`, see comments inside the `latexmkrc` files of the `zip` archive I attached to earlier post
