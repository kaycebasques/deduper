After investigating the three reported behaviors, they appear to have separate causes:

1. The inconsistent `Literal` linking is still reproducible and appears to be tracked more specifically by #10525.
2. `numpy.typing.ArrayLike` is an intersphinx `py:class`-to-`py:data` mismatch. The equivalent local mismatch is fixed by #13808, but the intersphinx fallback remains unresolved. I added a detailed reproduction and proposed fix to #10974, which also has reports of this external behavior.
3. The `Tensor` and `Shape` cases do not appear to be reference-resolution failures. In the linked pyhf revision, neither alias is included in `autodoc_type_aliases`, and the generated API documentation does not register either as an indexed object. Sphinx therefore has no target to resolve. The local fallback in #13808 only helps when an alias is already documented as `py:data` or `py:attr`.

I do not think a single fix covers all three reports. I suggest tracking the `Literal` behavior in #10525 and the intersphinx fallback in #10974.
