I want also to suggest the following changes. Currently `:meta field: value` is only used with `:meta flag:` without any value. Instead, I suggest extending this behaviour in order to allow a generic metadata:

- The metadata can be written on multiple lines (in the docstring) using `\` as a separator. Currently, the metadata is assumed to be written on a single line, but if `:meta field: value` exceeds the allowed line length, the metadata is incorrectly parsed. I will open a separate issue for this.

- The metadata object is a dictionary mapping metadata fields to their value. I had developed an extension to handle arbitrary metadata and use them to inject options into the autodoc directive that is being used, the underlying `py` directive (e.g., `autoclass` and `py:class`) or an inner directive as well.

I think that this feature would help a lot of people that are too lazy (like me) to write `.rst` docs and put everything directly at the code level (like me).
