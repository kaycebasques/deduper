I use `autodoc` because I prefer documenting everything at the code-level. However, autodoc does not consider autodoc directive options that can be present in the docstring itself, except for some `:meta ...:` fields.

However, the current implementation suffers from the following drawbacks:

- The metadata must be on a single line in the docstring. 
- The metadata dictionary is not cached by autodocumenters.
- The metadata values cannot be used to extend documenters options.

As such, I extended the docstring parser for joining lines continued by `\` and created an interface for interacting with the metadata. For instance (assuming that `autoclass` supports `:synopsis:` similar to `automodule`):

```rst
.. autoclass:: MyClass
   :show-inheritance:
   :noindex:
   :undoc-members:
```
```python
class MyClass:
    '''
    This is a docstring.

    :meta enable: members
    :meta disable: show-inheritance, no-index
    :meta set: synopsis = 'a very long synopsis \
                           must be broken with \
                           trailing backslashes'
    '''

    def foo(self):
        pass
```

would be equivalent to:

```rst
.. autoclass:: MyClass
   :members:
   :synopsis: a very long synopsis must be broken with trailing backslashes
```
```python
class MyClass:
    '''
    This is a docstring.
    '''

    def foo(self):
        pass
```
