**Is your feature request related to a problem? Please describe.**

In Japanese, sphinx uses TinySegmenter, mecab, or janome to split the sentence into the words to create the search index.
BTW, on the browser, [searchtools.js](https://github.com/sphinx-doc/sphinx/blob/master/sphinx/themes/basic/static/searchtools.js#L174) uses very naive splitter by default.

For example, `逆引きレコード` is splitted to `['逆引き', 'レコード']` on the python side, but `['逆引きレコード']` on the browser in current sphinx implementation.

As a result, Japanese users can't search Japanese document on the sphinx without some hacks.

There's an extension to solve this problem: https://github.com/whosaysni/sphinx-tsegsearch/
But so, i want to search Japanese documents out of the box.

**Describe the solution you'd like**

TinySegmenter is originally written in JavaScript. as a result, we can use it without any issues.

Following operation only runs  when `html_search_language=='ja' and html_search_options['type'] == 'sphinx.search.ja.DefaultSplitter'`. write custom_splitter.js and load it before loading searchtools.js.

(Note, i want to support  mecab/janome... but it depends on the very large dictionary. it seems 20+ MiB. it's too large to load on the browser)
