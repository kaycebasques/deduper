> Could you please elaborate a little, perhaps with a sketch of what your intended end-state is?

Sure, imagine that I have a hierarchy of classes that all share a method:

    ClassA
    └── ClassB
        └── ClassC

They all share a method `method()` which I want to document. When generating the autosummary for `ClassC.method`, I want to be able to template the following result:

```rst
ClassC.method
=============

From bases:

.. method:: ClassA.method
            ClassB.method

.. automethod:: ClassC.method
```

At the moment, there is no mechanism to dynamically add a variable such as e.g. `bases` into the template, where `bases` depends on the object being rendered.

But let's not get hung up on my use case: Another simple scenario could be where some of what I am documenting has e.g. a `.displayname` property, and I want to dynamically make that available in my autosummary template:

```rst
{{ displayname | escape | underline}}

.. currentmodule:: {{ module }}

.. auto{{ objtype }}:: {{ objname }}
```

This could easily be achieved with the proposed event and a callback:

```py
def context_callback(app, name, obj, parent, context):
    return {'displayname': getattr(obj, 'displayname', name)}

app.connect('autosummary-context', context_callback)
```

I otherwise don't see a simple way to inspect the object being autosummarised, and dynamically providing context based on the result.
