### Problem
autodoc's `:exclude-members:` option can be used to exclude specific members from the auto-generated documentation. This works fine on the first level but nested identifiers (`a.b.c`) seem not to be supported.

Consider this Python source (`stest.py`)
```python
class A(object):
    '''Documentation for A'''
    def a(self):
        '''Documentation for A.a'''
    def b(self):
        '''Documentation for A.b'''

class B(object):
    '''Documentation for B'''
    def c(self):
        '''Documentation for B.c'''
    def d(self):
        '''Documentation for B.d'''
```
The following reST correctly documents all members of `stest`:

```rst
.. automodule:: stest
    :members:
```

I now would like to hide `A.b` from the auto-generated documentation. I can hide `A` completely via

```rst
.. automodule:: stest
    :members:
    :exclude-members: A
```
but this does not work for excluding `A.b`: the following reST simply documents all members (including `A.b`).

```rst
.. automodule:: stest
    :members:
    :exclude-members: A.b
```

I know that I can work around this by specifying a separate `autoclass` entry for both `A` and `B` and passing an `:exclude-members: b`  option to the `autoclass` entry of `A`. This may work for small modules, but for big modules it would be much easier if nested identifiers were supported as arguments for `:exclude-members:`. Obviously this shouldn't be limited to one level (`a.b`) but support arbitrarily nested identifiers.
