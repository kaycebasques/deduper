I fiddled with this a while. I can reproduce it without sphinx-js with this `index.rst` file in a Sphinx project:

```rst
Welcome to testproj's documentation!    
====================================    
    
.. py:function:: request_callback(response_code)        
    
   :param int response_code:    
   :type response_code: int    
    
    
.. js:function:: requestCallback(responseCode)    
    
   Some global callback    
     
   :param number responseCode:                                                 
   :type responseCode: number    
```

With Sphinx 3.5.2, doing `make text` produces this text output:

```
Welcome to testproj's documentation!
************************************

request_callback(response_code)

   Parameters:
      **response_code** (*int*) --

requestCallback(responseCode)

   Some global callback

   Arguments:
      * **responseCode** (*number*) --
...
```

With Sphinx 4.1.0 and later (including Sphinx 5.3.0), it produces this:

```
Welcome to testproj's documentation!
************************************

request_callback(response_code)

   Parameters:
      **response_code** (*int*) --

requestCallback(responseCode)

   Some global callback

   Arguments:
      * **responseCode** ("number()") --
...
```

I traced the `make_xref` code around and the key difference is that the Python domain has a `PyXrefMixin` that changes the call to `make_xref` setting `Inliner` to `None`:

https://github.com/sphinx-doc/sphinx/blob/d8977d3e5785b02adca5ee001b0d9cdcd6a22ef0/sphinx/domains/python.py#L335-L339

Because there's a non-None `Inliner`, then this `if` conditional triggers differently between the two function docs:

https://github.com/sphinx-doc/sphinx/blob/d8977d3e5785b02adca5ee001b0d9cdcd6a22ef0/sphinx/util/docfields.py#L74

Because the `rolename` is `func`, then the result is markup for a function.

With Python, since the `Inliner` is `None`, it does the pre-4.1.0 behavior.

Should all domains be setting `Inliner` to `None`? Why does the type get a rolename of `func` in the first place? Should we not be using the `type` info field for arguments in JavaScript functions?
