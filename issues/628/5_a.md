So, I found the line of code that discovers the inherited members in the mro in the [`get_class_members`](https://github.com/sphinx-doc/sphinx/blob/0b17bb1029f6ff18b1a90461ca6f51415eca54fc/sphinx/ext/autodoc/importer.py#L317) function :
https://github.com/sphinx-doc/sphinx/blob/0b17bb1029f6ff18b1a90461ca6f51415eca54fc/sphinx/ext/autodoc/importer.py#L348
Here the members added *in alphabetical order* as `dir` always uses alphabetical ordering. That seems like a bit of a mistake, as sorting alphabetical could be (and actually is) easily done at a later point, but having the original order initially should probably be done here.

I change the line to the following to save them in source order:
```python
for name in [name for cls in subject.mro() for name in cls.__dict__.keys()]:
   ...
```
This allows for inherited-members to be shown in by-source order and, after a quick test, it seems that alphabetical ordering also still works with this patch.
