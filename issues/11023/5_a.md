I actually encountered something similar about the behaviour of the `:download:` role, also when trying to download "uncommon" files (like a jupyter notebook).

On Chrome and Firefox, the download is correctly executed and the file is saved with the correct extension. However _Safari_ does not like this, and either downloads the file by adding a `.txt` or a `.html` extension. I'm not sure at this point which extension is triggered when TBH.

By playing around with the DevTools, adding `download="some_file_name.ipynb"` to the `<a>` tag restores the correct behaviour in Safari. As far as I undestand, it's not possible to hook into sphinx to fix this by listening to events, because of this part of the code:

https://github.com/sphinx-doc/sphinx/blob/2fa51bb49351cff4e3c67adafbe51ecfd0fdb43b/sphinx/writers/html5.py#L719-L737

It's impossible to set `atts['download']` to anything from the outside, before the `a` tag is written. Is there a reason why `download` is set but not to any particular filename?
