Same issue encountered with classes inheriting from a framework that defines `__new__(**kwargs)`. A workaround using the `autodoc-process-signature` event to pull the signature from `__init__` directly:

```python
# conf.py
import inspect

def _fix_class_signature(app, what, name, obj, options, signature, return_annotation):
    if what == 'class' and '__init__' in obj.__dict__:
        sig = inspect.signature(obj.__init__)
        params = [p for p in sig.parameters.values() if p.name != 'self']
        return (str(inspect.Signature(params)), None)

def setup(app):
    app.connect('autodoc-process-signature', _fix_class_signature)
```

This checks if the class defines its own `__init__` and uses that signature instead of whatever Sphinx introspected. Works on 7.4 and should be stable across versions since `autodoc-process-signature` has been around since 0.5.

Can be scoped to specific modules with a `name.startswith(...)` check if needed.
