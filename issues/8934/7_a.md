Also, I realized it hasn't been specified in this issue previously that lack of PEP 613 support for automatic type alias generation also impacts usage of [`NewType`](https://docs.python.org/3/library/typing.html#newtype) ([PEP 484](https://peps.python.org/pep-0484/#newtype-helper-function)). While `TypeAlias` is admittedly kind of moot now that PEP 695 support enables the newer `type` syntax, `NewType` is still very useful for specifying derived classes, which `type` and `TypeAlias` are currently unable to indicate.

In my case, `NewType` is particularly useful in cases where the exact type implementation is not available, but it is known to derive from something else. In this situation, `NewType` can be used to enable meaningful type analysis where we might not otherwise have access to the explicit definition. E.g., I'm working with an externally-defined data structure (i.e., non-Python) called `Foo`, that is known to derive from and extend another data structure `Bar`. `NewType` can be used to indicate this relationship intuitively.

You can hack it to work with `autodoc_type_aliases` by using `type Foo = NewType('Foo' Bar)` instead of just `Foo = NewType('Foo' Bar)`, but this isn't actually valid syntax (to my understanding) and still requires manually specifying the type alias rather than being automatically parsed.
