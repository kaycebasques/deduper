### Describe the bug

When using autosummary with recursion and option `:nosignatures:`, the option is only applied to the top level and not passed on to submodules. This is a problem, because Sphinx extensions can treat the presence of a signature significantly different than just displaying humble parentheses `(…)`.

For example, with `"sphinx_autodoc_typehints"`, I get this (which I want to disable in my summaries):
![image](https://github.com/sphinx-doc/sphinx/assets/54448967/7836f4b7-cfbf-40fc-8478-5a6f3391051d)

### How to Reproduce

#### Example

Assume a project of the following structure:
```shell
my_module
├── __init__.py
└── submodule.py
```
where `submodule.py` contains a more detailed implementation:
```python
def function_with_complex_signature(
    arg1: str,
    arg2: tuple[float, float],
    arg3: dict,
) -> tuple[list[tuple[float, float]], dict, str]:
    pass
    return [(0, 0)], {}, ""
```

Sphinx with extension autosummary:
```python
extensions = ["sphinx.ext.autosummary"]
autosummary_generate = True
```

and index.rst with `:recursive:` and `:nosignatures:`:
```reStructuredText
.. autosummary::
   :toctree: generated/
   :recursive:
   :nosignatures:

   my_module
```

#### Actual behavior

The html page `my_module.submodule.html` lists the function with signature.
![image](https://github.com/sphinx-doc/sphinx/assets/54448967/6f6f2690-2c76-4775-a33f-e3b9d567ff41)

#### Expected behavior

- The signatures of functions in nested modules should also be hidden.
- With recursion, options should apply to all submodules, since there is no other way to configure them separately (other than no recursion and listing the nested entries explicitly in the directive).
