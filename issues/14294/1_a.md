**Is your feature request related to a problem? Please describe.**
`xarray` and `pandas` have a concept called "accessor", which allows extending the main classes (e.g. `xarray.Dataset` or `pandas.Series`) with a namespace object. This namespace object can make full use of python's data model, including special methods like `__getitem__` or `__call__`.

To allow documenting these namespace objects more easily, I created [sphinx-autosummary-accessors](https://github.com/xarray-contrib/sphinx-autosummary-accessors), which provides a set of templates and associated `autodoc` documenters. These rewrite the real and displayed paths of the documented member to display them the way they are called (e.g. we'd display `xarray.Dataset.hvplot.image` instead of `hvplot.plotting.core.hvPlot.image`). However, while this works perfectly fine for the pages rendered by `autodoc`, there does not appear to be a way to do the same for the table generated by `autosummary`.

Note that these documenters are not designed to be usable in general, so I can't just set the priority high enough that they'll always be used.

**Describe the solution you'd like**
A way to explicitly specify the documenter instead of working around the guessing machinery in `autosummary`.

If we can arrive at a design that would allow me to get this to work, I can try to create a PR that does the necessary changes.

**Describe alternatives you've considered**
Override `Autosummary.get_items`. This would definitely work, but would be a lot of work to maintain across multiple versions of `sphinx` (and I'd still be using private API).

**Additional context**
Following an earlier discussion (see #7908) I arrived at overriding `Autosummary.create_documenter`. However, after the refactor in `sphinx==9.0.0` this method does not exist anymore, so I am looking for a better way to implement this (and hopefully one that uses the public API).
