**Is your feature request related to a problem? Please describe.**
The `python_use_unqualified_type_name = True` only uses unqualified names if the type is documented. This means that `TypeVar`s, which are typically not documented, are always printed fully qualified. This tends to make signatures unnecessarily verbose.

**Describe the solution you'd like**
I would like an option that will print specifically `TypeVar`s always unqualified. The option may be named `python_use_unqualified_typevar_names`. When the option is `True` it will print `TypeVar` variables unqualified unconditionally. When it is `False` it will fall back on the decision selected by `python_use_unqualified_type_name`. It should default to `False` for backwards compatibility. 

**Describe alternatives you've considered**
Creating project-global `TypeVar`s and then documenting them so they all resolve to the same documented type and the names are printed unqualified. This is very atypical. `TypeVar`s are not typically shared between multiple modules. Nor should they be documented, which may make the user think they are for public use.
