> An alternative is to implement a similar logic to what I've done for PEP 695 but for C++ so that templates are properly formatted.

This problem isn't limited to templates: it's just where I've surfaced the problem. It would be best if Sphinx just deferred to dedicated tooling (when available) so that projects don't need to have multiple config files with conflicting opinions on how to "properly" format. Ideally, the declarations in the documentation would be formatted the same way as in source.

This is especially relevant for C, C++, and possibly Objective C---which unlike more modern languages---don't have a canonical formatting style. The [clang-format style options page](https://clang.llvm.org/docs/ClangFormatStyleOptions.html) gives a taste of what kinds of things different people prefer to have in their respective codebases. Many C, C++, and Objective C programmers defer formatting to clang-format, though a colleague informed me that emacs and vi both have highly-customisable autoformatters as well. Even Python has various autoformatters, so being able to plug those in would be useful.
