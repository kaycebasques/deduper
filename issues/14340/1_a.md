### Describe the bug

If one module defines properties named like Python builtins (`int, str, list, type`) and another module uses builtin type annotations (`int, str, list[str], dict[str, int]`), generated API docs may create incorrect cross-references. This also occurs if explicit type hints like `builtins.int` are being used.

The builtin types are linked to those same-named properties instead of being rendered as plain builtin types with no link.

### Expected behavior

Builtin type annotations are shown without links to class members.

### Actual behavior

Builtin type annotations are linked to properties with the same names. Even if the properties itself are directly typed e.g. as `builtins.str` the link being rendered leads to the property with the same name --> to itself.
