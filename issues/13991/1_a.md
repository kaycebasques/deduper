### Describe the bug

Building the docs with the `autosummary` directive enabled to document a class that has a property named as the class raises the error below:

```
Traceback
=========

      File "/private/tmp/ad/.venv/lib/python3.12/site-packages/sphinx/ext/autodoc/__init__.py", line 2407, in import_object
        obj = self.parent.__dict__.get(self.object_name, self.object)
              ^^^^^^^^^^^^^^^^^^^^
    AttributeError: 'property' object has no attribute '__dict__'. Did you mean: '__dir__'?
```

I think it's the unfortunate result of a prefix+name that can be accessed while it should not. In this case, the code looks for `foo.__init__` to document the `__init__` method of the `foo` class. However, it ends up finding instead `pkg.mod.foo.foo.__init__`, which is the `__init__` method of the property object. This happens in `_import_by_name`.

### How to Reproduce

```python
# pkg/mod.py
class foo:
    """Demo class whose property name collides with the class name."""

    def __init__(self):
          self._value = "hello"

    @property
    def foo(self):
          """Property docstring you expect autosummary/autodoc to show."""
          return self._value
```

```python
# pkg/__init__.py
# empty
```

```python
# docs/conf.py
import os, sys
sys.path.insert(0, os.path.abspath(".."))

project = "autosummary-bug"
extensions = ["sphinx.ext.autodoc", "sphinx.ext.autosummary"]
autosummary_generate = True
templates_path = ["_templates"]
html_theme = "alabaster"
```

```
.. docs/index.rst

Pkg API
=======

.. currentmodule:: pkg

.. autosummary::
  :toctree: generated
  :nosignatures:

  mod.foo
```

Command to run: `sphinx-build -b html docs docs/_build/html`
