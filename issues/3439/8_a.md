I concur, that would be a marvellous feature. 

When writing long passages of text I use the marginal column to summarize (as it would be on a presentation slide). For many kinds of texts this works very well. In LaTeX I created a layout which uses two thirds of `\textwidth` for the main text and one third of `\textwidth` for marginal notes. 

When switching to Sphinx I ran into the very same problem. The `sidebar`-directive seems to be a sensible choice, but is not formatted properly when using the LaTeX builder (html using the read-the-docs-theme is no problem, it renders as exspected). 
As a temporary workaround I have redefined the `sphinxShadowBox`-environment in a special style class where I keep all my Sphinx-related LaTeX modifications: 

`\RequirePackage{environ}\RenewEnviron{sphinxShadowBox}{\marginpar{\BODY}}`

The downside is all the chapter table of contents are now moved to the margin as well. Simply putting the `sidebar`-content into another environment at build time (and putting the content of this environment in the margin) would solve the problem. 

Personally I see no reason for not putting the _side_ bar content to the _side_ (=margin).
The current behaviour/output of the LaTeX builder is counterintuitive.
