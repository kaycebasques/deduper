Currently, C++ functions are assigned internal identifiers for the purpose of HTML linking based on a mangling scheme.  This results in unique ids that are order-independent, which is good, but can result in ids that are not as stable as might be desired.  In particular, you may add an additional parameter with a default value, or change a parameter type, in a way that is source compatible but results in a different manged id, which will break links from prior versions of the HTML documentation.

I propose as an alternative that the user be able to specify an explicit overload id, e.g. via a `:overload-id:` option to `cpp:function`, that would be used along with the fully-qualified name to identify the function, in place of the mangling scheme:

```
/// Does something or other with Foo.
///
/// Overload:
///   foo
void func(Foo foo);

/// Does something or other with Bar
///
/// Overload:
///   bar
void func(Bar bar);
```

This would result in HTML ids like `func-foo` and `func-bar`.  Furthermore, the user could reference these overloads using `func(foo)` and `func(bar)`, which may be much more convenient if there are complicated parameters that would make specifying the full signature challenging or annoying.

See also https://github.com/sphinx-doc/sphinx/issues/7296#issuecomment-824352910 where I first proposed this.
