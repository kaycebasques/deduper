I propose this to be out of scope for core sphinx and thus close this. If somebody is interested, it should instead be implemented as a third-party plugin.

`:file:` is a pure markup role and should not be overloaded with reference semantics (see also the mentioned complication). An implementation should use a different role name such as `:fileref:` or or similar. So there is no coupling to the existing code.

This is a specialized variation of the glossary pattern (centralized list and roles linking to list entries). We shouldn't go down the rabbit hole of trying to accomodate every special use case.
