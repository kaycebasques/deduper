### Describe the bug

In [CMake](https://cmake.org/cmake/help/latest/), we often have references like `` :command:`list(APPEND)` ``. We used to explicitly strip the argument lists, but I recently implemented a feature that allows such references to be resolved to a specific signature. However, `XRefRole.update_title_and_target` explicitly adds `()`, even if parentheses are already present, resulting in e.g. `list(APPEND)()`.

I can work around this by reimplementing `update_title_and_target`, but it seems like Sphinx shouldn't be doing that in the first place?

While there is "logic" to test for this, that logic is `if title.endswith('()')`. It almost seems like the opening parenthesis in that test should be omitted?
