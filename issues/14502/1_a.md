### Describe the bug

With `show-inheritance` enabled and `nitpicky = True` (or `-W`), documenting a class whose base is `Generic[_T]` — where `_T` is an undocumented module-level `TypeVar` — makes the rendered **Bases:** line emit a cross-reference to the TypeVar:

```
WARNING: py:obj reference target not found: mod._T [ref.obj]
```

A `TypeVar` is not a documentable object, so this cross-reference can never resolve. The Bases line should render the TypeVar as text (the way `typing` reprs a TypeVar) rather than as a `py:obj` cross-reference.

This is `sphinx.ext.autodoc` core behaviour — it reproduces with no other extensions loaded (in particular it is **not** `sphinx-autodoc-typehints`), and it disappears when `show-inheritance` is turned off.

### How to Reproduce

`mod.py`:

```python
"""Minimal module."""
from typing import Generic, TypeVar

_T = TypeVar("_T")


class Foo(Generic[_T]):
    """A generic class with a private TypeVar."""
```

`conf.py`:

```python
project = "mre"
extensions = ["sphinx.ext.autodoc"]
nitpicky = True
autodoc_default_options = {"members": True, "show-inheritance": True}
```

`index.rst`:

```rst
MRE
===

.. automodule:: mod
   :members:
```

Build:

```console
PYTHONPATH=. sphinx-build -W -b html . out
```

```
<unknown>:4: WARNING: py:obj reference target not found: mod._T [ref.obj]
build finished with problems, 1 warning (with warnings treated as errors).
```

Removing `"show-inheritance"` from `autodoc_default_options` makes the build pass, which confirms the dangling reference originates from rendering the `Generic[_T]` base.

### Expected behavior

The TypeVar in the base class is rendered as plain text (no cross-reference), so a `nitpicky` / `-W` build succeeds. Undocumented TypeVars should not produce unresolvable `py:obj` references.

### Your project

Minimal reproducer above.

### Additional context

Real-world hit when a class subclasses `Generic[...]` with private (underscore-prefixed) TypeVars, e.g. `class MockClient(Mock, Generic[_I_contra, _O_co])`. The only workarounds today are disabling `show-inheritance`, dropping `nitpicky`/`-W`, or adding the TypeVars to `nitpick_ignore` — all of which mask the problem rather than rendering the base correctly.
