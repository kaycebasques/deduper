This is a stickier change than it looked like at first glance. There are two options IMO:
 - Create the RateLimit tuple the first time we see a given domain instead of the first time we receive a "Retry-After" response.
   -  this probably makes all sphinx users have a bad day
 - Have a configurable list of vulnerable domains (e.g. www.gnu.org) that aren't able to use dynamic rate limiting for whatever reason
 
A bonus 3rd option would be 
 - add `mod_evasive` or similar, assuming gnu.org is still on Apache?

What is the path of least resistance here?
