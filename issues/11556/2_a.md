The reason why the **HTML** was rebuilt is because the HTML file did not exist anymore. The `_build/html` is the output HTML directory but the latter is only put as an artifact and not cached (at least that's how I see it, I haven't checked that this is really the case). 

Concerning your documentation request, to my understanding, this is what happens:

- The environment decides which `.rst` files are using `BuildEnvironment.get_outdated_files`. More precisely, it determines which `.doctree` file to write. It is based on whether the `.rst` original file is modified or not (using mtime values) or if one of its dependencies was modified. 
- In an incremental build approach (`Builder.build_update`), the following is done:
  * Determine which output (e.g., HTML) files are outdated using `Builder.get_outdated_docs`.
  * Determine which source (RSt) files are outdated using `BuildEnvironment.get_outdated_files`.
  * Write the output (HTML) files corresponding to the outdated source or output files.

Let's illustrate this by an example. Assume that we have the following RST files:

```rst
.. index.rst 

.. toctree::
   :maxdepth: 1

   bar.rst
```

```rst
.. foo.rst

The Foo
-------
foo
```

```rst
.. bar.rst

The Bar
-------
and the foo:

.. include:: foo.rst
```

- Run Sphinx first. The three documents will generate `_build/doctrees` containing the serialized docutils tree. The first time you run Sphinx, all three documents are marked as "added" (they are fresh).
- If you change `bar.rst`, the latter is marked as changed. As such `_build/doctrees/bar.doctree` will be updated. Since `bar.rst` was changed, `_build/html/bar.html` is marked as updated by `Builder.get_outdated_docs`. Which HTML file to rebuild is decided by whether on the timestamp of the original source (i.e., `bar.rst`) and compared with the timestamp of the HTML file. 
- If you change `foo.rst`, all the files depending on `foo.rst` are to be rebuilt as well. In particular, `bar.rst` must be rebuilt. Here, note that `Builder.get_outdated_docs` will not include `bar.rst` because `bar.rst` was not modified as a file. However, `BuildEnvironment.get_outdated_files` will include `bar.rst` as a document that was "virtually" changed.
