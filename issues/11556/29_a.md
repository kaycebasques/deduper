With recent changes (including #13676 & #13681), we are in a position to consider checksum/hash-based change detection. This could either augment or replace the current change detection that is based on modification-time.

On my computer, calculating an SHA-256 hash from the content of a file takes ~2.6x longer than obtaining the last modification time (76ms vs 29ms for a directory tree with c. 800 files). This is fairly large from a microbenchmark perspective, but I believe acceptable in the context of the application as a whole.

Questions:

* Is there value to using an expensive hash over e.g. a CRC32 checksum?
* Are there use-cases for the mtime-based approach that would be broken if we used checksums?
* Would this actually solve the GitLab problem?
