> 
>     * Docutils 0.21+ allows some image files in source `rST` projects to be annotated as for embedded use;

No. The "tagging" happens in the reStructuredText source in the "image" directive using its :loading: [option](https://docutils.sourceforge.io/docs/ref/rst/directives.html#image-options).
 
>      this means that each relevant image file is not included in the output build as a standalone named file, but is instead replicated (perhaps using `data:` URIs, embedded XML, or other formatting as available based on the output format and image type) each time the image is referenced, from each output document that references it.

Almost. Docutils does not copy images to a build directory. By default the HTML `<img>` just refers to the image file's URI specified in the rST source.

With `:loading: embed`, the Docutils html5 writer converts image URI-References to local file paths and inserts SVG images as embedded SVG and all other images via data URIs.
 
> Could I also ask what behaviour `docutils` provides if-and-when writing such embedded-annotated images to a purely text-based output format?

In output formats that don't support images, the :loading: option is ignored.
