When using the `option` directive, the latex writer generate code using `\index`. But this `\index` is used at a location which may be separated by page-break from actual description of option.

For example, Sphinx own doc contains in `invocation.rst`

```
Project basic options
---------------------

[ lines cut]

.. option:: --suffix=SUFFIX

   Source file suffix. (see :confval:`source_suffix`).
```

in latex output this gives

```latex
\index{sphinx-quickstart command line option!--suffix=SUFFIX}\index{--suffix=SUFFIX!sphinx-quickstart command line option}

\begin{fulllineitems}
\phantomsection\label{\detokenize{invocation:cmdoption-sphinx-quickstart-suffix}}\pysigline{\sphinxbfcode{-{-}suffix}\sphinxcode{=SUFFIX}}
Source file suffix. (see {\hyperref[\detokenize{config:confval-source_suffix}]{\sphinxcrossref{\sphinxcode{source\_suffix}}}}).

\end{fulllineitems}
```

and when building the doc (a4paper), (my build was done using `1.6.4+/8542e29b4`), the page number and link in the general index point back to page 9, but the actual text appears at top of page 10.

When viewing the pdf on screen, when one clicks on the page number in the index one ends up at top of page 9 and one wonders where the entry actually is.

### Environment info
- OS: Mac
- Python version: 3.5.4
- Sphinx version: used a sphinx.pdf build from stable branch at 8542e29b4
