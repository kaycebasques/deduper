This is a similar to #9394 which is about napoleon not making a hyperlink for return types, although there's a subtle difference. In both cases, napoleon is translating this raw docstring to RST format, so the key question is: what should the underlying RST look like for everything to be formatted correctly?

For return, the documented way is to use `:return: Description goes here.` followed by `:rtype: TypeName`. That's not ideal at the best of times because the type appears on a separate line, and its unworkable for multiple return values. The fix, as I discussed in #9394, is to change the underlying `:return:` directive to support an optional type parameter and support automatic grouping into bullet points (#13920). Then napoleon would be able to use that.

Yields is a bit different because, at the moment, napoleon translates it to the `:yields:` directive ... but there is no `:yields:` directive! There is simply no corresponding notion in the Python domain. The fact that it does anything at all is because Sphinx [has a fallback for unknown docfields](https://github.com/sphinx-doc/sphinx/blob/b9d5d2bacca83edcd6f7cb10c63490ec1b29fccd/sphinx/util/docfields.py#L403) that just capitalises the directive name and sticks a colon on the end. Notably, I wouldn't expect "Yields:" to internationalise properly.

The correct fix for this is still similar to the one for returns though: add (rather than change) a field type to the Python domain to represent `Yields`, and use type `PyGroupedField` for it.

(Side note: I know the picture is just an example, but if the return type is `Iterable[int]` then the yield type is surely just `int`. To be honest, I think it's clearer just to give its return type.)
