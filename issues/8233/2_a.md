> When a sub-class defines an override for init, if a docstring isn't provided autodoc pulls the docstring from the parent class constructor. This doesn't make sense since the override can present a different set of arguments.

That seems to be a general problem, not specifically related to `__init__`: if a member is overloaded with no docstring, the docstring is automatically pulled from the parent. Neither `undoc-members` nor `inherited-members` seem to affect this. It's generally frustrating but especially when the original docstring contains *explicit targets*: now every child class which overrides the method without having its own docstring will trigger a warning e.g.

```python
class Foo:
    def bar(self):
        """ This is a Bar

        blah blah

        .. _specific/reference:

        more text
        """

class Baz(Foo):
    def bar(self):
        """ overrides docstring """

class Qux(Foo):
    def bar(self):
        ...
```
```sh
reading sources... [100%] thing                                                                                                                                                                                    
/tmp/testproj/src/thing.py:docstring of thing.Qux.bar:5: WARNING: Duplicate explicit target name: "specific/reference".
looking for now-outdated files... none found
```

That looks to be [Python's built-in behaviour since 3.5](https://docs.python.org/3/library/inspect.html#inspect.getdoc):
> Changed in version 3.5: Documentation strings are now inherited if not overridden.
