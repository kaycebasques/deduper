**Is your feature request related to a problem? Please describe.**
For async functions written in Rust, and exposed as function or method with pyo3, with a signature like this:
```rust
/// This method does something
///
/// :param some_param: toto
/// :type some_param: float
///
fn toto<'py>(slf: Bound<'py, Self>, py: Python<'py>, some_param: f64) -> PyResult<Bound<'py, PyAny>> {
    pyo3_async_runtimes::tokio::future_into_py(
        py,
        async move {
            # my rust async code
        },
    )
}
```
autoclass or automethod do not detect that `toto` is actually a coroutinefunction, i.e. it is called from Python
as
```python
await titi.toto(49.3)
```

**Describe the solution you'd like**
The ideal solution would be to be able to specify that the signature is async directly in the
docstring. For exemple using `:async:` like I can do manually with `.. py::method` if I were to write the documentation manually.

**Describe alternatives you've considered**
The alternative would be the manually specify `:async:` for each method inside `.. autoclass`, e.g.
```rst
.. autoclass:: Toto

   .. automethod:: toto
      :async:
```
but it is cumbersome.
