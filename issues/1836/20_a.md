My use case is a bit different, I would like to maintain the **SDMX Standard's documentation** from the various repositories it comprises of under one main documentation site (HTML + PDF downloads). I would like to leave the oportunity and responsability to each "sub-"repository to update their documentation but have only one TOC.

- [sdmx-im](https://github.com/sdmx-twg/sdmx-im/tree/I1-doc) : contains the TOC & base documentation
  - [sdmx-ml](https://github.com/sdmx-twg/sdmx-ml) : contains the doc for the XML format
  - [sdmx-json](https://github.com/sdmx-twg/sdmx-json) : contains the doc for the JSON format
  - [sdmx-rest](https://github.com/sdmx-twg/sdmx-rest) : contains the doc for the API
  - ...

and the TOC has sections that correspond to the main documentation and repositories.

_This would mean that the sub-section in the TOC would be expanded from the TOC hierarchy of the sub-repositories._

See [here a trial publication](http://docs.sdmx.org/en/i1-doc/)
