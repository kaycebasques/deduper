**Is your feature request related to a problem? Please describe.**
Making [code-blocks translatable](https://github.com/python/cpython/issues/123407) in Python docs has caused some issues in tooling connected with translations' quality assurance:
* spellchecker wrapper pospell is [crashing when parsing](https://git.afpy.org/AFPy/pospell/issues/17) [codeblocks](https://github.com/python/python-docs-es/issues/3324), but even without crashes we wouldn't like to spellcheck Python code, at most only comments
* sphinx-lint library expects [PO entries to consist of valid reStructuredText](https://github.com/sphinx-contrib/sphinx-lint/issues/120), and some code-blocks were failing the linting because of that; those are fixed in Python docs, but potentially some new cases may arise.

**Describe the solution you'd like**
I would like to propose to make the Sphinx gettext builder leverage [flags in PO files](https://www.gnu.org/software/gettext/manual/gettext.html) to mark the entries coming from code blocks as such. That would enable downstream tooling to interpret those flags and use them to ignore or change behaviour for such entries.

**Describe alternatives you've considered**
A workaround is being practiced by [some](https://github.com/python/python-docs-pt-br/pull/234) [teams](https://git.afpy.org/AFPy/python-docs-fr/commit/b60c43cca29486c9502365af6f590e9e7ffd038a), that builds gettext with disabled code-blocks, merges and reports on the translation quality basing on it.

**Additional context**
Gettext documentation doesn't explicitly allow or disallow custom flags for entries (it presents a list of officially supported flags). Some of the gettext utilities [are said to remove custom flags](https://savannah.gnu.org/bugs/?60947), but general direction for the project is to persist them throughout transformations.

Additionally recently [it was announced that there's a second syntax for flags](https://lists.gnu.org/archive/html/bug-gettext/2025-06/msg00018.html), that we could consider taking into account when implementing the solution.
