### Describe the bug

I have the `autodoc_default_options` field `"special-members"` set to `True` and  the `"undoc-members"` field left at the default of `None`. With this configuration I would expect only documented special members be included in the generated document. Instead, it seems to be randomly including some special members which are given generic default docstrings. It's particularly weird because even within one class, one set of methods will be documented incorrectly and others won't.

See the generated docs [here](https://coconext--77.org.readthedocs.build/en/77/reference.html#coconext.types.BitArray). `__eq__`, `__or__`, `__ror__`, `__str__`, and `__repr__` are all implemented in this class (see [here](https://github.com/ktbarrett/coconext/blob/dev/src/coconext/types/_bit_array.py)), none of them are documented, but they are shown with generated docstrings. Strangely, `__and__`, `__rand__`, `__xor__`, `__rxor__`, and `__invert__` are also implemented in this class, don't have a docstring, but correctly don't show up in the generated docs.
