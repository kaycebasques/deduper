Pretty much a novice of sphinx and auto-summary, but I happen to have stumbled upon the source of the problem: The default template has the line 

```
.. currentmodule:: {{ module }}
```

which attempts to import - well - `module`; however, in the case of nested classes `module` is actually pointing to a class instead of a module. Naturally, the resulting import fails.

A more wise person than me should suggest what a good solution to this problem is/should be; however, a workaround is to use your own class template that doesn't attempt to include the module. For example the default template, but with all the relative pathing removed. This isn't 100% ideal, because the names can get unpleasantly long; however it may be a first start.

```
{{ fullname | escape | underline}}

.. autoclass:: {{ fullname }}

   {% block methods %}
   .. automethod:: {{ fullname }}.__init__

   {% if methods %}
   .. rubric:: {{ _('Methods') }}

   .. autosummary::
   {% for item in methods %}
      ~{{ fullname }}.{{ item }}
   {%- endfor %}
   {% endif %}
   {% endblock %}

   {% block attributes %}
   {% if attributes %}
   .. rubric:: {{ _('Attributes') }}

   .. autosummary::
   {% for item in attributes %}
      ~{{ fullname }}.{{ item }}
   {%- endfor %}
   {% endif %}
   {% endblock %}
```

Perhaps one can view this as a fault of `module` not pointing to an actual module, and the fix should be implemented there ... I don't know. Just putting this out there, in case it may be useful to some :)
