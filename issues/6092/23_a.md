Using the Docutils methods in a `sphinx.ext.mathml` module has some problems:

* Naming: 
  Docutils' HTML [math output](https://docutils.sourceforge.io/docs/user/config.html#math-output) can be MathML, HTML, MathJaX, or verbatim LaTeX.
An extension named "mathml" that outputs HTML is confusing.

* Sphinx additions:
  Sphinx overrides the Docutils "math" directive and role with its own implementation adding the options `:label:` and `:no-wrap:`. 
Also the `<math>`  and [`<math_block>`](https://docutils.sourceforge.io/docs/ref/doctree.html#math-block) doctree elements are extended and use attributes like "docname", "label", and "number" that are invalid in Docutils and ignored by the converter.

* Stability:
  There are [plans]( https://docutils.sourceforge.io/RELEASE-NOTES.html#misc) to move the math format conversion from docutils/utils/math (called from docutils/writers/_html_base.py) to a [transform](https://docutils.sourceforge.io/docs/api/transforms.html) (see also the [Docutils To Do List](https://docutils.sourceforge.io/docs/dev/todo.html#math-markup)).
