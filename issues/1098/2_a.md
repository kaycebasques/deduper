This idea is paramount. Callouts in asciidoc are a key advantage and should be incorporated into sphinx to keep up.

I have a couple of suggestions for this idea.

---

(1) This may be an implicit assumption of Martin's proposal, but :callouts: specifiers (e.g. "<1>"), that are not explicitly assigned should render without any substitution to maintain backwards compatibility of documentation sources.

```
#!restructuredtext

.. annotated-code-block::
   :callouts-style: circled|negative circled|
   :callouts-render: unicode|images|svg|css3

    .. code-block:: python

        def greet(name):
            print 'Hello', name
        greet('Jack')             <1>
        greet('Jill')             <2>

    .. annotation::
       :callouts: <2>

         Description
```

should render

```
#!python

        def greet(name):
            print 'Hello', name
        greet('Jack')             <1>
        greet('Jill')             ②
```

② Description

---

(2) The readability of :callouts: elements could be improved by simply allowing them to be in-line, ensuring that suggestion (1) above is honored. This obviates :position: elements, and is consistent with the philosophy that the plain-text should be able to serve for documentation as effectively as rendered text.

```
#!restructuredtext

.. annotated-code-block::
   :callouts-style: circled|negative circled|
   :callouts-render: unicode|images|svg|css3

    .. code-block:: python

        def greet(name):          <3>
            print 'Hello', name
        greet<3>('Jack')          <1>
        greet('Jill')             <2>

    .. annotation::
       :callouts: 2

         Description

    .. annotation::
       :callouts: 3
       :character: a

        Another description
```

should render (note three characters of "<3>" was substituted by one character "ⓐ")

```
#!python

        def greet(name):           ⓐ
            print 'Hello', name
        greetⓐ('Jack')           <1>
        greet('Jill')              ②
```

② Description

ⓐ Another description
