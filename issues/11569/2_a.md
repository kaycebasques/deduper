Ah yes, I know of this issue. I've also stumbled upon this kind of issue when using my local sources. Here, the reference Sphinx is trying is `requests_oauthlib.oauth1_auth.OAuth1`. However, the intersphinx mappings actually contains only the entry `requests_oauthlib.OAuth1` probably because it's been exported from the `requests_oauthlib.oauth1_auth`module. I think we have similar issues when importing return type annotations in a `if TYPE_CHECKING` block by the way (but not sure whether it's an issue on master). 

The way I fixed this is by defining which reference should be resolved to which "real" item and used a `SphinxPostTransform` for that.
