### Describe the bug

I've noticed this in 4.3.2 through 5.1.1.

Consider something like the following:

```

.. include:: /includes/common/foo.rst
  :start-after: start-some-key-desc
  :end-before: end-some-key-desc
```

Lets say that the key ``end-some-key-desc`` doesn't exist in the referenced file.

The ideal output should be:

```
/home/user/docs/source/includes/common/foo.rst:112: CRITICAL: Problem with "start-after" option of "include" directive:
Text "end-some-key-desc" not found.
```

The actual output is:

```
/home/user/docs/source/includes/common/foo.rst:112: CRITICAL: Problem with "start-after" option of "include" directive:
Text not found.
```

This is barely useful for debugging purposes. At least for the example above, if the include has no further nested includes, I can go to line xyz and see the issue.

But if I have any level of nested includes, Sphinx seems to get lost and returns errors like the following:

```
<rst_prolog>:26: CRITICAL: Problem with "start-after" option of "include" directive:
Text not found.
```

I've had similar errors where Sphinx points to lines where there are no includes at all, and the actual broken link is completely unrelated.

I could use some guidance here in general - we're trying to make good use of includes for single-sourcing, but without that key information it doesn't get too far.

### How to Reproduce

Create a standalone project.

Create some include files

Reference them using broken `:start-after:` and `:end-before:` descriptors

Experiment with nested includes

### Expected behavior

For errors related to `:start-after:` and `:end-before:`, ideally the returned error should include the actual search text to make identification of the include easier.
