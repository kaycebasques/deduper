This issue is to enhance the index directive by adding support for creating indexes beneath auto-generated index entries (e.g. perhaps by adding additional index entry types).

Background: Sphinx automatically creates specially-formatted index entries for certain types of objects.  For example, for the built-in function `open()`, Sphinx creates an index entry that looks like "open() (built-in function)".

To create a sub-entry below this auto-generated entry, one can create an entry like the following:

```
single: open() (built-in function); file object
```

However, this approach is brittle because it relies on hard-coded strings in, for example, [PyModulelevel.get_index_text()](https://github.com/sphinx-doc/sphinx/blob/1f905f121ad7131678c5b0b571ecf10e189a9676/sphinx/domains/python.py#L250).

It would be nice if instead one could do something like the following inside an index directive (using the corresponding role syntax):

```
_func: open; file object
```

And similarly for classes, methods, attributes, etc.
