I'm using the Sphinx to document C code. Sometimes, it's useful to document the "direction" of a parameter (is it used to pass data in or is it an pointer filled by the called function). Doxygen, for example, supports the syntax `@param[in] some_parameter description` for this case. It would be nice to extend the Sphinx C (and possibly C++) domain with this support as well.

Syntax proposal:

Variant 1
```rst
.. c:function:: status_t* some_function(some_t *indata, result_t **results)

   Do something interesting

   :param some_t indata: The input data (no direction documented)
   :param out result_t results: The output will be written to this variable
```

Variant 2
```rst
.. c:function:: status_t* some_function(some_t *indata, result_t **results)

   Do something interesting

   :param some_t indata: The input data
   :param result_t results: The output will be written to this variable
   :type results: result_t
   :dir results: out
```

I'd have a look at the implementation myself, but I got a bit lost in the field type implementations. Maybe a hint where to get started for this support would already be enough for a patch from my side.
