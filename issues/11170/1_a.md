### Describe the bug

The `#:` annotations from a base class are shown for both instance and class attributes in a child class, unless the parent inherited TypedDict.
The attributes of both parent and child class will be listed but only the child's will have inline annotations.
In the example code below making Foo inherit another class does not break it, but if it inherits TypedDict it does, and conversely removing TypedDict from the FooOptions will make it work.

The reason I would like to do this inheritance of the TypedDict subclass is to typehint and annotate two or more classes who accept several optional arguments so best unpacked and Python 3.11's Unpack[TypedDict] works nicely in Sphinx (without inheritance) for this purpose.

### How to Reproduce

Say I have two classes Foo and Bar whose named arguments are typehinted by FooOptions and BarOptions:

```python
import sys

from typing import Dict, TypedDict
if sys.version_info.minor < 11:
    # for backwards compatibility outside of the the RTD build only
    # as this will not work in sphinx
    from typing_extensions import TypeVarTuple, Unpack
else:
    from typing import Unpack, TypeVarTuple

class FooOptions(TypedDict):
    """
    foo options
    """
    # this is normal comment...
    a: int  #: I like bacon
    b: str  #: I like eggs


class BarOptions(FooOptions):
    """
    bar options
    """
    c: float  #: I like spam
    d: bool   #: I like spam with spam
    e: Dict[str, int]  #: I like spam with spam and spam

class Foo:
    foo_class_attribute: int = 0  #: I like spam in my foo class attributes

    def __init__(self, **options: Unpack[FooOptions]):
        self.foo_instance_attribute: int = 1  #: I like spam in my foo instance attributes
        pass


class Bar(Foo):
    """
    this is Bar class. More extras than Foo.
    """
    bar_class_attribute: int = 0  #: I like spam in my bar class attributes

    def __init__(self, **options: Unpack[BarOptions]):
        foo_options = {k: v for k, v in options.items() if k in FooOptions.__annotations__}
        super().__init__(**foo_options)
        self.bar_instance_attribute: int = 2  #: I like spam in my bar attributes
        pass
```
Now when I generate its documentation with the following settings:
```
.. autoclass:: test.Bar
   :members:
   :undoc-members:
   :inherited-members:
   :show-inheritance:


.. autoclass:: test.BarOptions
   :members:
   :undoc-members:
   :inherited-members: dict
   :show-inheritance:
```
The unpack TypedDict in Bar is a lovely link and all is great bar for one detail:

I will get the `#:` annotation for attributes in Bar even if it was defined in Foo, but not the `#:` annotation from a & b in BarOptions which were defined in FooOptions —these attributes will be there however, just without the annotation.
