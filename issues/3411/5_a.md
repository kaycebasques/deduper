> Problem however is that `:widths:` is interpreted by Sphinx as proportions. 
Hence currently `300, 700` is equivalent to `30, 70`. It is not clear from Docutils doc if this is correct way to interpret the `:widths:`. 

The [documentation](https://docutils.sourceforge.io/docs/ref/rst/directives.html#table-options) was updated to clarify the interpretation of the "list of integers":

"Explicitly set column widths. Specifies relative widths if used with the width option."
"list of integers: Must match the number of table columns. Used instead of the input column widths."

In other words: if the :width: option is specified, `300, 700` is equivalent to `30, 70`.
If no table width (:width: option) is specified, a "list of integers" is interpreted similar to the input column widths -- which depends on the writer:

HTML: table width is determined by the browser based on content and colum-width ratio.
LaTeX: table width is determined in `docutils.writers.latex2e.Table.get_colspecs()` based on the sum the column widths (either input charaters or list of integer :widths:).
The algorithm assumes 40 characters to equal 100% linewidth (for details see the comments in the source). This value was found to result in the best approximation of input table dimensions with article documentclass, A4, Times fonts, and default margins.

If the input column widths are used, an "allowance" of 1 is added to each column-width integer (as the values in the doctree nodes do not include inter-column space).
