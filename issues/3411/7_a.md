> Some things remain very obscure though when Docutils mentions "input column widths". 

*Input column widths* refers to the width of the columns in simple tables or grid tables in characters. The parser computes them from the first line of the table markup and stores them in the [colwidth](https://docutils.sourceforge.io/docs/ref/doctree.html#colwidth) attributes of the table's `<colspec>` Doctree elements. 

Example: the following rST input
~~~rst
== ===    ======
A  B      C
== ===    ======
~~~
generates the `colwidths` 2, 3, and 6.

>How are substitutions, hyperlinks, included lists, sub-tables, etc... counted when determining such "input column widths"? What about verbatim contents, is wrapping of code lines allowed? etc... etc...

The content of the input table columns is irrelevant.
What counts is only the layout of the input grid table or simple table. 

This simple algorithm provides good estimates for use cases where the intended column widths can be easily indicated in the table markup.

In other cases the default colwidths are sub-optimal:

* If the input table must use wide colums to contain footnote definitions, hyperlinks or other markup, the input column widths may become unsuited as indicators for "good" output column widths.
* The "list-table" and "csv-table" directives cannot use table markup and default to 
`colwidth = int(100/number_of_columns)`

This is why the :widths: option exists.
For example, the colwidth values in the above example can also be achieved by
~~~rst
.. table::
   :widths: 2 3 6

   ======  =  ==
   A [#]_  B  C
   ======  =  ==
~~~
or
~~~rst
.. list-table::
   :widths: 2 3 6

   * - A
     - B
     - C

~~~

-----------------------------------

If the table width is specified via the `:width:` attribute, the `colwidth` values are only used for relative column widths. 
If the table width is not specified but the output format requires a value for the table width (LaTeX with body elements in table cells), the absolute `colwidth` values may be used to compute a default value.
