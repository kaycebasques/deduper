But in the case of [list tables](https://docutils.sourceforge.io/docs/ref/rst/directives.html#csv-table) or [csv tables](https://docutils.sourceforge.io/docs/ref/rst/directives.html#csv-table)  there is no "original table like input".  Anyway, here is Sphinx definition of the `\Y` column type:
```
\newcolumntype{\Y}[1]{p{\dimexpr
      #1\dimexpr\linewidth-\spx@arrayrulewidth\relax-\tw@\tabcolsep-\spx@arrayrulewidth\relax}}
% \spx@arrayrulewidth is used internally and its meaning will be set according
% to the table type; no extra user code should modify it.  In particular any
```
For tables using vertical rules `\spx@arrayrulewidth` is the (usually `0.4pt` if I recall correctly) width of vertical dividers.  A column is bordered both on left and right by `\tabcolsep` horizontal space if it is has not been canceled by specific preamble (which Sphinx user can inject via `tabularcolumns`). So, this definition makes it though, that columns of types `\Y{f1}\Y{f2}...\Y{fN}` will let the table fill exactly (inclusive of its left and right vertical lines if any) the `\linewidth` if `f1+f2+...+fN=1`.  If the sum is not exactly one, the space occupied is `(f1+f2+...+fN)\linewidth+(1-f1-f2-...-fN)<used rule width>`, which was deemed good enough.  And anyhow is exactly `(f1+f2+...+fN)\linewidth` for tables with no vertical lines, which is nowadays the default for Sphinx.  I am mentioning this formula and explaining it, because I don't see then why the `f1`, `f2`, ..., `fN` parameters should take into account whitespace in-between columns: they already refer to the total width of the column, inclusive of such left and right whitespace and inclusive of one vertical line width.
