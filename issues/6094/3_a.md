@marcoricci rather than LaTeX ``listings`` approach it looks far better to use Sphinx own already existing rendering of code blocks with Pygmentize library. It is a fact that currentil ``viewcode`` extension has only support for HTML like rendering, but you can always use the [literalinclude](https://www.sphinx-doc.org/en/master/usage/restructuredtext/directives.html?highlight=literalinclude#directive-literalinclude) directive.

> The file name is usually relative to the current file’s path. However, if it is absolute (starting with /), it is relative to the top source directory.

```
.. only:: latex

   .. literalinclude:: myfile.py
```

See the options of [literalinclude](https://www.sphinx-doc.org/en/master/usage/restructuredtext/directives.html?highlight=literalinclude#directive-literalinclude) such as ``:pyobject:``.

```
.. only:: latex

   .. literalinclude:: myfile.py
      :pyobject: myfunction
```
 
Surely this is a better approach than the listings based one. But it does not solve this issue as it still requires handwritten manual additions to source files.
