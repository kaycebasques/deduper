Yes, using `:name: server001` etc does work, and puts an anchor into each page, as I noted when I first created this ticket.

The feature I'm suggesting is to have an anchor put into the generated index so that we can link to *that*. So, in HTML the index page would have something like this (I'm going to simplify the HTML from what Sphinx generates to make what I'm suggesting more obvious):

```
...
<li><a href="server-types.html#storage-hosts" id="storage hosts">storage hosts</a>
<ul>
    <li><a href="servers/diskly-001.html#index-0">diskly-001</a></li>
    <li><a href="servers/diskly-002.html#index-0">diskly-002</a></li>
...
```

See the "id=" on the index entry for "storage hosts"? Having an anchor like that would allow us to say `see in the index all servers of type :ref:"storage hosts"`  (I can't put backticks in the `:ref:` due to gitlab limitations). It would also allow the "see also" index entries to link directly to the other index entry instead of being plain text and requiring people to scroll around (or for PDFs etc page back and forth.
