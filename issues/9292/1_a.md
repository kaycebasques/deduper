**Describe the bug**

When a doc website A contains a term in a glossary such as `Open Energy Phase 3`, that term can be referenced locally. If, however, that term is referenced from a second doc build B, by adding an intersphinx reference to A, it does not resolve. It appears that any term ending with a numeral is subject to this issue.

**To Reproduce**
Steps to reproduce the behavior:

Add the following intersphinx reference:

```
'oe': ('https://icebreakerone.github.io/open-energy-technical-docs/main/', None)
```

Then attempt to reference a term ending in a numeral from a second project, i.e.

```
:term:`Open Energy Phase 3` - this fails when accessed through intersphinx
```

**Expected behavior**

References to terms in external projects linked through intersphinx resolve in the same way as those defined locally, in this case the term should resolve rather than failing.

**Your project**

https://github.com/icebreakerone/open-energy-technical-docs contains source, https://icebreakerone.github.io/open-energy-technical-docs/main/index.html is the site containing the manifest from which I'm trying to import terms.

**Environment info**

Sphinx build run from linux, python 3.8.6, sphinx 4.0.2
