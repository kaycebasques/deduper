### Describe the bug

When using `autodoc_member_order = 'groupwise'`, simple type aliases (e.g., for primitives) are not sorted together with more complex type aliases like `typing.Union`.

### How to Reproduce

```
$ git clone https://github.com/cimes-isi/sphinx-type-alias-sorting.git
$ cd sphinx-type-alias-sorting
$ pip install sphinx
$ cd docs
$ make html
```

Open `docs/build/html/testmod.html` and see that simple type aliases are sorted with classes, rather than together with other type aliases.


### Expected behavior

Type aliases should be grouped together when using `autodoc_member_order = 'groupwise'`.

### Additional context

PEP 613 introduces explicit type aliases for type hints (`typing.TypeAlias`).
Explicitly declaring a TypeAlias type hint might resolve the sorting issue (I don't have Python 3.10 to test with), but requires Python >= 3.10 and imposes additional burden on the source code to make Sphinx work as expected without any actual runtime benefits.

Maybe type aliases could/should be their own sorting group.
It seems like currently it's mixing them with classes and data, depending on the alias.
