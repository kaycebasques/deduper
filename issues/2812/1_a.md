In the case that I want to use nested domain directives, but also include non-nested elements, such as headings, a `hidden` directive helps to re-establish nesting. That is:

``` rst

.. js:class:: Foo

Foos
----

.. js:class:: Foo
    :hidden:
    :noindex:

    .. js:method:: foo_bar()

    .. js:method:: foo_baz()

Bars
----

.. js:class:: Foo
    :hidden:
    :noindex:

    .. js:method:: bar_foo()
```

Output from this:
- Doesn't prefix all directives with the class name
- Doesn't index secondary, hidden directives
- Doesn't require me to use rubrics

I implemented this change on `sphinxcontrib-dotnetdomain`:
https://github.com/rtfd/sphinxcontrib-dotnetdomain/blob/master/sphinxcontrib/dotnetdomain.py#L285-L299

Would this make sense as an addition to the top-level `ObjectDescription` class? Happy to write up a patch if this feature would be accepted.
