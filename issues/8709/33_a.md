Further analysis means that we could check if the id is empty before making the id-xyz ID 

If it's empty, re-perform normalisation, but before zeroing, add a id- prefix to the original ID, such that `7.0.0 (2025-10-3)` becomes `id-7-0-0-2025-10-3` which is different only in the leading characters if it were to start with an alphabet character. (`id-7-0-0-2025-10-3` vs `v7-0-0-2025-10-3`)

But in the event of `7.0.0 release`, normalisation would continue to normalize to `release`, and not have an impact.

This should keep nearly everything backwards compatible: the only IDs that would be impacted are ones that already have inconsistent (id-<xyz>) IDs, such that the entire header is normalized to removed code and therefore not used.
