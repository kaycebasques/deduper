I don't think this would be an improvement over the current framework, where the output writer gets the "document" tree as a Python data structure and the "HTML translator" uses a "visitor pattern" calling transformation methods for each of the document tree's node.

The "element visiting" methods are called with the respective element node object as argument and hence have access to all its attributes + internal attributes + parents + children.
