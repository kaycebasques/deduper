@tk0miya I use a monkey patch as a workaround in this [commit](https://github.com/MegEngine/Documentation/commit/233b8bafcfb2a48d8e8c87cbec5ca35f96dedc2e):

``` python
# project_dir/source/conf.py
# 
# -- Monkey patch for `mprop` package ----------------------------------------
# It will make some module to be a instance for getting or setting property
# That is good for improving user experience but Sphinx can not handle with it
# So we add a monkey patch then mprop will do nothing while building the doc.

def doNothing(*args):
    return

import mprop
mprop.init = doNothing
mprop.mproperty = property
mprop.auto_init = doNothing

# Then import your package
```

Then add an `autosummary` template in `source/_templates/autosummary/mprop.rst`:

```rst
{{ fullname | escape | underline}}

.. currentmodule:: {{ module }}

.. autodata:: {{ objname }}
```

Then use it in corresponding API ref `.rst` file:

```rst
.. autosummary::
   :toctree: api
   :nosignatures:
   :template: autosummary/mprop.rst

   eviction_threshold
   evictee_minimum_size
   enable_sqrt_sampling
```

I think **Module Property** is a very interesting design, and it may become more common in the future.

Hope there will be more native Sphinx solutions with `mprop`.

If you have a better idea, can't appreciate more.
