**Is your feature request related to a problem? Please describe.**
It would be nice if aliased functions and methods displayed "alias of [original]" in the generated documentation, just like aliased classes currently do. Likewise for exceptions and attributes, although I think aliases for those are less common so it's not as important.

**Describe the solution you'd like**

In the example below, `foo_alias` and `bar_alias` should display as "alias of [foo/bar]" in the generated documentation.

```python
class A:

    def foo(self): ...

    foo_alias = foo

def bar(): ...
bar_alias = bar
```


**Describe alternatives you've considered**
I guess this could be an optional behaviour, but I don't think it's optional for class aliases and I think the behaviour should be consistent.

**Additional context**

I recently implemented aliases for methods and functions in SageMath, although it's perhaps hackier than it could be if it were part of sphinx itself. https://github.com/sagemath/sage/pull/40753

A few edge cases that might cause complications:

- Lambda functions
- Public aliases of private functions/methods
- Alias of a function that is in a different module
