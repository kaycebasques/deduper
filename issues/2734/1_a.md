Doctests contained within the same file are executed in a nice predictable order. Sometimes it's important for test execution order across multiple doctest files to be ordered as well.

For example, say I have a toctree in my index that looks something like:

```
.. toctree::

    database-setup
    application-stuff
```

Assume 'application-stuff' requires that the tests run in 'database-setup' to be run beforehand. It's not the case that these files are actually tested in the order they are listed in the toctree. Ideally, there would be a mechanism or naming convention to enforce ordering.
