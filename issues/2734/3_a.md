Test files are still ordered by Sphinx, which uses a Python `set` to order files. This doesn't really do much to ensure that test cases are independent, as tests cases can still be ordered across files if you get lucky enough.

However if you're not lucky, this imposes a somewhat arbitrary restriction on how a document can be structured. If your document gets large enough, you may want to start splitting things up into separate files, even if it means splitting up related tests. I always thought that one of the benefits of Sphinx is that it provides ways of splitting up your document into a collection of files, rather than one big monster.

That said, my specific use-case was to use Sphinx's doctest extension for something more like literate programming than testing, which is likely not a typical usage pattern.
