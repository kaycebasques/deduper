PEP 695 type parameters are not registered in the Python domain's reference context during signature parsing and class-level directive processing, leading to spurious cross-reference resolution failures for these local identifiers in nitpicky mode.

Consider:
- Modify _parse_type_list to return the names of the parsed type parameters.
- Update PyObject.handle_signature to temporarily store these names in env.ref_context['py:type_params'] while parsing the rest of the signature.
- Update PyObject.before_content and after_content to manage a persistent py:type_params stack for class-level type parameters.
- Modify type_to_xref to check env.ref_context['py:type_params'] and avoid creating a pending_xref for local type parameters, returning a simple name node instead.
- Alternatively, update resolve_xref to recognize type parameters passed via node attributes and silence the warning.
