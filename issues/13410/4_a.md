Hi again @AA-Turner if it helps narrow things down, I'm pretty sure that what's happening is that something like `*args` or `**kwargs` is being generated for the `__init__` method of a dataclass, and that the single asterisk (or double asterisk) in the signature is being interpreted as reST start-emphasis (that then goes "unmatched" with closing asterisk).

In addition to the example at the start of this thread, there are two other places in my codebase where 8.2.x generates this same "Inline emphasis start-string ..." warning. And they are here, which are the only two dataclasses in my codebase that use `*arguments` in their initializer:

@dataclasses.dataclass(order=True, slots=True, unsafe_hash=True)
class Breaks:

    pages: list["Page"] = dataclasses.field(default_factory=list)

    def __init__(self, *arguments: "Page"):
        for page_number, argument in enumerate(arguments, start=1):
            assert isinstance(argument, Page), repr(argument)
            if argument.number != page_number:
                message = f"page number ({argument.number}) is not {page_number}"
                raise Exception(message)
        self.pages = list(arguments)


@dataclasses.dataclass(order=True, slots=True, unsafe_hash=True)
class Page:

    number: int
    systems: list["System"] = dataclasses.field(default_factory=list)

    def __init__(self, number: int, *systems):
        assert isinstance(number, int), repr(number)
        self.number = number
        assert all(isinstance(_, System) for _ in systems), repr(systems)
        self.systems = list(systems)
