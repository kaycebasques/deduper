### Describe the bug

When using the Intersphinx extension to add clickable links pointing to items in the official Python 3 docs, if a builtin Python function is referred to as ":py:obj:\`funcname()\`" (note parentheses) — or as just "\`funcname()\`" when `default_role` is set to `"py:obj"` — then Sphinx will be unable to resolve the reference, a warning will be output in nitpicky mode, and the function name in the rendered HTML will not be a hyperlink.  However, if the function is referenced as ":py:func:\`funcname()`", with or without parentheses, then Sphinx is able to resolve the reference.  The same problem happens with methods.

Also note that including parentheses in an Intersphinx class reference like "\`str()\`" will never produce a clickable link, regardless of whether :py:obj: or :py:class: is used.

For contrast, when cross-referencing Python objects in the Python module being documented, "\`funcname()\`" is properly resolved, and class references can include parentheses and still be clickable links.

### How to Reproduce

```
$ git clone https://github.com/jwodder/sphinx-bug-20220618
$ cd sphinx-bug-20220618
$ tox -e docs
$ # Open docs/_build/html/index.html and see the results shown below
```


### Expected behavior

Intersphinx function & method references should resolve when using the `py:obj` role, regardless of whether parentheses are included, and intersphinx class references should resolve for both the `py:obj` and `py:class` roles when parentheses are included.
