**Is your feature request related to a problem? Please describe.**
I am trying to put together documentations from various sub projects in one place. These subprojects may run in different environments so it is not always possible to make all the libraries available in the same environment. Therefore I would like to extract autodoc and autosummary from them in one step, and then use the generated rst files in another environment. This will also enable me to only update the documentation related to the updated sub project.

**Describe the solution you'd like**
I would like to be able to cache and store the output of the autodoc directives (which does not require importing of modules). like attempted [here](https://github.com/brenthuisman/sphinx-autodoc-cache/blob/main/autodoc_cache.py) so I can use it later while compiling some other docs or at a later time.

**Describe alternatives you've considered**

1. I have tried to use external linking, but it does not provide search mechanism
2. I have tried to use [affiliates](https://github.com/mattip/sphinx-affiliates) but that extension is still patchy and unmaintained.
3. I will try to use mocks to import all subprojects to the same sphinx environment but it will increase compile time and may also limit features like inheritance diagrams.
4. I may also use autoapi (static analyzer), but that comes with the issues related with static code analysis.
