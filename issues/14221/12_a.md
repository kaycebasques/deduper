So, what `fix_refuris` seems to be used for is that for hyperlinks that _would_ otherwise feature both a document-path (e.g. `#glossary/term1`) _and_ also a term-label (e.g. `#term-API`), it drops the former -- `SingleHTMLBuilder` is the sole internal user of this.  It works because in the resulting HTML, glossary terms -- regardless of the use of `fix_refuris` -- are emitted solely with the term-label as element ID.  The HTML looks like:

```html
<dt id="term-API">...</dt>
```

So: as a longer-term fix, I'd suggest:

A) Including a document-path part in the glossary term HTML element idenfitiers - e.g. expand them to `<dt id="glossary/term1#term-API">...</dt>`

**AND**

B) URLencode the term-label when they are referenced by HREF - e.g. `<a href="#document-glossary/term2%23term-API">...</a>`

I've tested that proposed approach in Firefox 140.5.0 and it results in functional glossary-term hyperlinks within a single HTML page.  As a small bonus, it enables disambiguation of hyperlinks when the same glossary term (e.g. `API`) is defined in multiple document glossaries.
