As of Sphinx 1.6 (and commit https://github.com/sphinx-doc/sphinx/commit/edc7f30b9cc92f4d721eeef62ffa826f23a09a9f) the smart quoting search / replace operates at the parsing step of the doctree, rather than at the output (Writer) stage.  See the commit.

I don't think this change is correct, although I can see it is convenient from the point of view of using docutils code.  It forces all output writers to deal with fancy unicode characters that were not in the original ReST file, to no good purpose, it seems to me.  For example, the fancy quotes now appear in the output of the `text` builder, when previously the output text files would have only the ASCII characters that were in the original ReST.   This makes the text files more difficult to parse for simple text readers.

For my own application, I am building Markdown and Python script versions of pages.  For the same reason, these Markdown / Python code files have unexpected and unwanted fancy quote unicode in them now, when they did not have them previously.

See [this thread](https://groups.google.com/forum/#!topic/sphinx-dev/v43JedWILR0) for some extra discussion, and some breakage introduced by this change.

Would you consider reverting commit https://github.com/sphinx-doc/sphinx/commit/edc7f30b9cc92f4d721eeef62ffa826f23a09a9f ? Or refactoring so that the transformation is at the writer stage rather than the doctree reading stage?
