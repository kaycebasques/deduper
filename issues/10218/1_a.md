**Is your feature request related to a problem? Please describe.**
I'm attempting to document multi-word options, which are typical for CLI commands with subparsers, but I cannot get multi-word references to work.

To illustrate this I will use `aws` command which is rather extreme because of it's deep nesting: `aws ec2 describe-instances --dry-run`

The `option` syntax _seemed_ obvious at first glance so I tried:
```
.. program:: aws
.. option:: ec2 describe-instances --dry-run
```
... but it does not allow me to reference this with:
```
:option:`aws ec2 describe-instances --dry-run`
```

As far as I can tell the reference takes only the first word.

Minimal reproducer (with shorter strings and just two words): [index.rst](https://github.com/sphinx-doc/sphinx/files/8142601/index.rst.txt)

Build command:
```
sphinx-build -C -b html . _build index.rst
```

Error:
```
index.rst:5: WARNING: unknown option: rndc querylog on
```

**Describe the solution you'd like**
Assuming this is the right approach, then it would seem natural to me if `option` just took multiple words and the references then used the same words (with spaces in between). But honestly I cannot really foresee impact of this change.

**Describe alternatives you've considered**
1] A new "multi-work-option directive", but I think it is a bad idea. It will get quickly messy and confusing what option is documented using single-word vs. multi-word directive.

2] Another alternative would be to augment `.. program::`` with some sort of subparser support, possibly in form of `.. subprogram`` which would by itself be able to accept multi-word names. (Naming is hard, don't take string `subprogram` as too serious proposal.) It would then become:
```
.. program:: aws
.. subprogram:: ec2 describe-instances
.. option:: --dry-run
```
And reference would work "as usual" so the person who refers to the option does not need to know how it is split between program vs. subprogram vs. option:
```
:option:`aws ec2 describe-instances --dry-run`
```
