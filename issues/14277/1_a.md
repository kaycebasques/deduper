### Describe the bug

We're using sphinx for the [Godot engine documentation](https://docs.godotengine.org/en/stable/).
Our project is probably one of the larger ones using sphinx, with around 1,652 `.rst` files to be built (~34mb total).

The build takes around 1 hour. This is becoming a problem, as we're starting to regularly time out on readthedocs.

### How to Reproduce

"Minimal" won't do, I'm afraid, since this is a performance issue.[^1]
[^1]: It may be possible to auto-generate rst trees without any content or extensions. But I'm not sure this is helpful or needed.

If you want to try the build yourself, you can [download the repository](https://github.com/godotengine/godot-docs) and build [according to our guide](https://contributing.godotengine.org/en/latest/documentation/manual/building_the_manual.html).

However, this may not be necessary. I've profiled using `cProfile`, and I'm sharing the result here. It should be possible to optimize our project by benchmarking and optimizing key bottlenecks from the profile result.

[results.prof.zip](https://github.com/user-attachments/files/24837977/results.prof.zip) (sphinx 8.1.3)
[results-master.prof.zip](https://github.com/user-attachments/files/24839537/results-master.prof.zip) (sphinx 9.1.0 / `master`)

(you can use e.g. [Snakeviz](https://jiffyclub.github.io/snakeviz/) or [flameprof](https://github.com/baverman/flameprof) to analyze the file)

Some quick insights:

- 1/3 of the time is spent in `_copy_except__document` 
    - Notably previously optimized in https://github.com/sphinx-doc/sphinx/pull/11565
    - Perhaps not duplicating more attributes could bring another boost?
- Another 1/3 of the time is spent in `core.py:218(publish)` (with self-time diverging from there)

I'm still investigating the results and seeing if there's any low hanging fruit to optimize. But we'd also appreciate any help in this effort.
