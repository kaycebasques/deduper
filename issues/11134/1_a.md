### Describe the bug

When an index is empty, no HTML page is generated and link to the index page are broken.

### How to Reproduce

Take the recipe example and change the last return line:

```py
class IngredientIndex(Index):
	"""A custom index that creates an ingredient matrix."""

	name = 'ingredient'
	localname = 'Ingredient Index'
	shortname = 'Ingredient'

	def generate(self, docnames=None):
		content = defaultdict(list)

		recipes = {name: (dispname, typ, docname, anchor)
				   for name, dispname, typ, docname, anchor, _
				   in self.domain.get_objects()}
		recipe_ingredients = self.domain.data['recipe_ingredients']
		ingredient_recipes = defaultdict(list)

		# flip from recipe_ingredients to ingredient_recipes
		for recipe_name, ingredients in recipe_ingredients.items():
			for ingredient in ingredients:
				ingredient_recipes[ingredient].append(recipe_name)

		# convert the mapping of ingredient to recipes to produce the expected
		# output, shown below, using the ingredient name as a key to group
		#
		# name, subtype, docname, anchor, extra, qualifier, description
		for ingredient, recipe_names in ingredient_recipes.items():
			for recipe_name in recipe_names:
				dispname, typ, docname, anchor = recipes[recipe_name]
				content[ingredient].append(
					(dispname, 0, docname, anchor, docname, '', typ))

		# convert the dict to the sorted list of tuples expected
		content = sorted(content.items())

		# return content, True
		return [], True
```

### Additional context

I'm trying to write a new extension for Sphinx. So I started with some online examples and the recipe example from Sphinx website. Due to the lack of good documentation for the data structures to return, I decided to start simple with returning an empty result. So I can test, if my extension was excepted and loaded.

Looking into examples and working extensions, there is always a possible execution path, where no index entry is returned, thus an empty results is a valid result.

When returning an empty index, this happens:
* No index page is generated as HTML file.
* The index page can be referenced by `:ref:` resulting in a correct but broken HTML link.
* Opening this link causes a 404 in the browser, as of cause no HTML page exists.
* There is no warning in the build log of an empty index causing no HTML page to be created.
* The index is not listed in the generating indices build entry, despite `generate` was called.

**Expected behavior:**
1. The index page (HTML) is generated, even if it's empty.
   * A message or admonition might be inserted denoting, that index is empty.
2. All `:ref:` roles and similar should work.
3. The index generation should be listet in the build log.
4. A warning should be raised in the build log, if an index is empty / useless.
