### Describe the bug

In the doctest section of the getting started tutorial:
https://www.sphinx-doc.org/en/master/tutorial/describing-code.html#including-doctests-in-your-documentation

Make it clear that the file: lumache.py
should be created in the project root directory, where the docs/ directory is located.

Because up to this point in the tutorial, we have been adding text and code to the files in the docs/source/ directory:
docs/source/conf.py
docs/source/index.rst
docs/source/usage.rst

And the incorrect assumption was that the file, lumache.py also should be created in the same docs/source/ directory.


The solution was found in this thread, from three years ago:
https://stackoverflow.com/questions/72822783/doctest-not-working-in-sphinx-cannot-import-python-files-python
> Move lumache.py to your project folder (i.e. same folder as where docs/ currently is).

This issue was also mentioned in this sphinx-doc repo comment from two years ago. https://github.com/sphinx-doc/sphinx/pull/11595#issuecomment-1679116515
> At this step, it is not clear where the file lumache.py is supposed to be created. If it is at the root of the docs directory, this step returns:


### Additional context

In hindsight, there are two subtle ways that the tutorial suggests that the lumache.py file should be created in another directory.
https://www.sphinx-doc.org/en/master/tutorial/describing-code.html#including-doctests-in-your-documentation
1. The comment in this code block:
```
# If extensions (or modules to document with autodoc) are in another directory,
# add these directories to sys.path here.
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parents[2]))
```

Why this isn't enough of a hint/description.
Not everyone that's learning sphinx knows python, and that parents[2] means that it will look for files in the same directory as the docs/ directory.
And the code block might just be copied and pasted into docs/source/conf.py, without being read.

2. The caption above the code blocks show the file path.

docs/source/conf.py
```
extensions = [
    'sphinx.ext.duration',
    'sphinx.ext.doctest',
]
```

docs/source/usage.rst
```
>>> import lumache
>>> lumache.get_random_ingredients()
['shells', 'gorgonzola', 'parsley']
```

For the file: lumache.py
it just shows the filename:

lumache.py
```
def get_random_ingredients(kind=None):
    return ["eggs", "bacon", "spam"]
```

Why this isn't descriptive enough.
The missing directory path, in the small code block caption, will likely go unnoticed.

The assumption will probably be, we're creating a new file, it must go in the same directory we've been working in docs/source/, since nothing else has been specified.
