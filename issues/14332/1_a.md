### Describe the bug

According to the changelog, autodoc was rewritten in Sphinx 9.0.0.

When building my project's docs, the following has started happening beginning with Sphinx 9.0.0:
One of the docs' pages calls the `automodule:: projectname.packagename` directive, which includes an attribute named `list` that's an alias of a class with a different name (not sure if the alias is relevant here).
Everything else in my project which has a type-annotation that includes something like `list[foo]` (from `builtins.list`) now has a reference to `projectname.packagename.list`, which is obviously wrong. This means that autodocs somehow puts `projectname.packagename.list` into the global namespace. If I set the `:no-index:` attribute, the problem goes away, but then the entire module obviously won't be listed in the toc.


### How to Reproduce

Reproduction:

```bash
   cd "$(mktemp -d)" \
&& python -m venv . \
&& source ./bin/activate \
&& pip install -q 'sphinx' \
&& mkdir foo bar \
&& sphinx-quickstart -q --ext-autodoc -p test -a test -r 0.0.0 -l en \
&& echo -e 'import pathlib,sys\nsys.path.insert(0, str(pathlib.Path(__file__).parent))' >> conf.py \
&& echo -e 'class MyClass:\n    """foo"""\n\nlist = MyClass\n\n__all__ = ["list"]' > foo/__init__.py \
&& echo -e 'from __future__ import annotations\n\ndef bar(a: list[str]) -> list[str]:\n    return a\n\n__all__ = ["bar"]' > bar/__init__.py \
&& echo -e 'foo\n===\n\n.. automodule:: foo\n    :members:' > foo/index.rst \
&& echo -e 'bar\n===\n\n.. autofunction:: bar.bar' > bar/index.rst \
&& echo -e '.. toctree::\n\n    index <self>\n    foo/index\n    bar/index' > index.rst \
&& sphinx-build -Q -b html . docs \
&& "$BROWSER" ./docs/index.html
```

`bar.bar(a: list[str]) → list[str]` includes links to `foo.list`, even though the type annotations are not related at all.

Replacing `'sphinx'` with `'sphinx<9'` works fine...
