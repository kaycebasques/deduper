Another way to implement this could be to add some kind of metadata (eg. `:toctree-only:` or `:group:`) to a page to indicate that the page should not be rendered and should not have a clickable link in the toctree.

While `:mindepth:` is intuitive given that `:maxdepth:` exists, it means that a single toctree directive must be split into multiple uses of the directive to be able to mix pages that should be included in their entirety and sections that should be partially included.

For example a set of documents like this:

```rst
.
├── changelog.rst
├── index.rst
└── user
    ├── index.rst
    ├── page1.rst
    └── page2.rst
```

Would need an index.rst like this:

```rst
.. toctree::
    :mindepth: 2

   user/index

.. toctree::

   changelog
```

Whereas if `user/index.rst` could contain this:

```rst
:toctree-only:

User Guide
=========

.. toctree::

    page1
    page2
```

Then `index.rst` could contain this:

```rst
.. toctree::

   user/index
   changelog
```

It also seems odd for an option on the toctree directive to control whether a page is rendered or not. A page can be rendered, but excluded from the toctree with `:orphan:`. So, to me at least, it makes sense for an option to also be able to control _how_ a page appears in the toctree.

Though note that this doesn't exactly address the typing documentation use case on its own.
