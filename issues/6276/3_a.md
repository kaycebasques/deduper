It works for me with Firefox and its pdf viewer. The labels are generated by hyperref package for the bookmarks. One can see them in file `foo.out` in Sphinx latex build repertory corresponding to file `foo.tex`.

The titles themselves are not very human-friendly in file `foo.out`: in UTF-16BE format, PDF-escaped ([direct reference to relevant section in hyperref pdf doc](http://mirrors.ctan.org/macros/latex/contrib/hyperref/doc/manual.pdf#nameddest=subsection.5.18)) but this is a detail.

- advantage of such preexisting targets is that the hypertarget opens the PDF right above the section title not immediately after it,

- disadvantage is that the actual names of destinations are the ones generated by hyperref itself although they seem quite guessable as the example above which is a link using ``manual.pdf#nameddest=subsection.5.18`` shows.

- of course a user chosen target name will remain identical throughout evolution of the document.

When the `bookmark` package  is loaded after `hyperref` the used file has extension `out.ps`, and its format is a bit different but for sectioning titles it seems the same.

My remarks above only explain that for sectioning units, the functionality is already existing with no change at Sphinx side...
