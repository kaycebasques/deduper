### Describe the bug

If an item does not have any docstring, `autodoc-process-docstring` does not run, preventing the user from being able to create one. 

If there is an empty docstring, the hook does run.

I found the issue as I'm adding a header to docstrings to state whether an item is inherited or not, with a link to the base class. Currently, inherited items that do not have a docstring will miss that header since the hook does not fire for them.

This seems to be an intentional behavior: https://github.com/sphinx-doc/sphinx/blob/ace5744b82345150baf3c71d6f47a257c89001ec/sphinx/ext/autodoc/__init__.py#L602

Would it be possible to revisit this aspect and use `docstrings = self.get_doc() or []` with no special case for None ? This fix works and should be backward compatible as well.
