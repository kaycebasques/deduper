The problem is here:

https://github.com/sphinx-doc/sphinx/blob/cc7c6f435ad37bb12264f8118c8461b230e6830c/sphinx/util/parallel.py#L89

If `logging.convert_serializable()` raises an exception, then the child process will die, and the pipe will close. The parent process then sees this as EOF.

By instrumenting `ParallelTasks._process` with `print()` to a uniquely-named file, I was able to see the traceback of the exception caused by `logging.convert_serializable(collector.logs)`.

In my particular case, there was a log entry with:
```
r.msg = "missing attribute mentioned in :members: option: module %s, attribute %s"
r.args = ('pw_elf.builder',)
```
which then raised an exception: `not enough arguments for format string`.

I will file a separate bug for that specific error once I track it down.

But in this case, sphinx needs to be defensive to ensure the result is always sent to the pipe.
