I'm writing extensive documentation using sphinx. Some commonly used modules are included as shared resources into these documentations. Having glossaries in this included documentation would help a lot. At the moment, this is not possible, because terms used in these included parts can always cause conflicts.

I see two simple solutions:
- Merging glossary terms from multiple sources into one central glossary with priorities.
- Allow separate glossaries with an additional identifier.

# Reasons for Multiple Glossaries

- Extensive documentation covering different fields with conflicting terminologies (design, math, coding). The same term has a different meaning in different parts of the documentation.
- Modular documentation with inserted documentation parts. E.g. three applications use the same library to provide some functionality. The documentation for this functionality is included in the documentation of the main application.

# Merging with Priorities

```
.. glossary::
    :priority: secondary

    term
        Secondary definition

    foo
        Foo definition

.. glossaty::
    :priority: main

    term
        Primary definition

    bar
        Bar definition
```

## Result

term
    Primary definition

bar
    Bar definition

foo
    Foo definition

Secondary definitions are never rendered at the original place where they are defined but in the main glossary.

# Separate Glossaries with Identifiers

```
Text with own :term:`terms<myid:term>`

.. glossary:: myid
    
    term
        Term definition
```
