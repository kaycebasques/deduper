Okay, thanks @jakobandersen for all the useful background on this.

I can understand the conceptual argument, and that `:` doesn't necessarily work in every Sphinx domain if `:` was a valid character, separator, e.t.c. for identifiers in that domain. However, particularly considering how much flak reST already gets for being unergonomic for non-expert writers, it's substantially longer and more syntactically complex for authors of (most?) domains that don't have this problem to have to type out, e.g., 

```rst
:external+python:py:func:`print`
```

instead of just

```rst
:func:`python:print`
```

or like in python/peps#3009

```rst
:external+py3.11:py:mod:`tarfile`
```

Instead of just

```rst
:mod:`py3.11:tarfile`
```

As the [good book](https://peps.python.org/pep-0020/) says, "practicality beats purity". Even @AA-Turner prefers the simpler syntax himself.

What about adding something like a `.. currentinventory::` directive that works like `.. currentmodule::` for explicitly selecting the default external inventory for the current document (unless/until used again, and maybe with an `:only:` option that disables local lookup)? This is a cleaner, more concise and much more ergonomic/user friendly solution for most cases (unless constantly switching back and forth between different explicit external inventories) than either the "extended syntax" or the `external` role.

I was actually going to suggest this already as due to strong need for it to e.g. point to a specific Python's version's docs, something that is heavily needed in the PEPs. In particular, it also makes it much easier and less noisy to change the default Intersphinx inventory for an existing document with one line, e.g. older PEPs, without having to modify every single usage. Better yet, it avoids having to repeat a bunch of boilerplate (`:external+inv-name:`) over in a document, which is highly tedious, error prone and frustrating for authors.
