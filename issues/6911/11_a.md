> > If the implicit name is not unique, you can specify the intersphinx target with an extended syntax:
> > See :exc:`MyException <pyExceptions:MyException>` for details.
> 
> This extended syntax is useful when linking to several versions of the same docs, but it's is not documented -- at least not in the [intersphinx docs](https://www.sphinx-doc.org/en/master/usage/extensions/intersphinx.html). According to those it should be `` :external+pyExceptions:exc:`MyException` ``. What's the difference between the two?

The ``external`` role was introduced because of problems with the extended syntax, so I suggest to never use the extended syntax, but switch to the "external" role.
The main problem with the extended syntax is that each domain (py, c, cpp, js, etc.) needs to support it, but using a `:` as delimiter is making it very complicated to do so in a clean way. As such an extended reference is anyway a direct query for intersphinx to do something, and not the domain, we decided to create the new role. The full discussion is in the PRs/issues somewhere, and it was part of a larger overhaul of intersphinx to support domains in a generic manner (though it has stalled from my side due to lack of time).
