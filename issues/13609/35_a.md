A clean fix for https://github.com/sphinx-doc/sphinx/issues/6026 as well as your "module directive" example would be to make sure the LaTeX writer handles `ids` for all elements.

An alternative to special-casing target elements whose `ids` were transferred to the next element would be to drop the `references.PropagateTargets` transform in its `get_transforms()` method. 
However, as the `references.PropagateTargets` transform is added by the "reader" component, it cannot be "unloaded" by a "writer".

Elements may have `ids` even without preceding `<target>` due to the [:name:](https://docutils.sourceforge.io/docs/ref/rst/directives.html#name) directive option. 
What is the Sphinx LaTeX writer output for
~~~
.. note::
   :name: my-note
   
   This is an admonition with ID
   
Link to my-note_. 
~~~
? (The Docutils LaTeX writer fails on this one, cf. [Docutils bug #503](https://sourceforge.net/p/docutils/bugs/503/).)
