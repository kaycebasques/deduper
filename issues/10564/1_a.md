### Describe the bug

When using autodoc to render a signature for a function that has an argument or return type that is parametrized by `AnyStr` (e.g., `Iterable[AnyStr]` — note that this happens regardless of whether `Iterable` is imported from `collections.abc` or `typing`), then the type parameters will be omitted in the rendered HTML.  I haven't tested this very fully, but Sphinx correctly handles `str` and `TypeVar("T")` as type parameters, so it's not a general type parameter issue.

For example, the following functions:

```python
from collections import deque
from collections.abc import Iterable, Iterator
from typing import AnyStr, TypeVar

T = TypeVar("T")


def anystr_iters(args: Iterable[AnyStr]) -> Iterator[AnyStr]:
    """
    The `AnyStr` parameters will be left off from the argument and return value
    of this function.
    """
    ...


def deque_func(queue: deque[str]) -> str:
    """This function is rendered fine."""
    ...


def deque_anystr_func(queue: deque[AnyStr]) -> str:
    """
    The `AnyStr` param will be left off from the argument of this function.
    """
    ...


def typevar_paramed(seq: list[T]) -> tuple[T]:
    """This function is rendered fine."""
    ...
```

are rendered as described in their docstrings; you can see a screenshot below.

### How to Reproduce

```
$ git clone https://github.com/jwodder/sphinx-bug-20220616
$ cd sphinx-bug-20220616
$ tox -e docs
$ # Open docs/_build/html/index.html and see the lack of `AnyStr` in the signatures for `anystr_iters()` and `deque_anystr_func()`
```


### Expected behavior

If a function or return type is annoted as `Foo[AnyStr]`, then Sphinx should render it as `Foo[AnyStr]`.
