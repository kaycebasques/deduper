Yeah, here is a simple example. I have multiple documents in my source directory. They all have frontmatter like this `:year: 2025` (with different years). Now, I want to generate a different page for each year that contains a list of all documents that have specified that year. E.g. `2025.html`.

I specifically want to _not_ use a html jinja template for this and instead _inject_ these virtual pages at an earlier stage so that they are output format agnostic.

This is a very simple example but this could e.g. be used to generate customizable slugs for blog pages, document location rewrites, getting content dynamically from some source etc.

One potential issue I see is with making the sources available. In all my tries of creating a little prototype I thus just set `html_copy_source = False`. 

I can implement this at the `env-updated` stage by manually creating doctrees, parsing rst, resolving references and storing the doctrees for writing. But it would be much nicer to just be able to tell sphinx to "restart" the build for some documents until `env-updated` is reached again.

Edit: I have since figured out how to do this in a smart way by using `env._registry.get_publisher` and creating a sort of "wrapper" for my virtual documents that has read and close functions. That way I can let anything (e.g. even just strings) act as the source documents that the publisher processes. Still working on the dependency tracking but I am working on a little extension that generalizes this now.
