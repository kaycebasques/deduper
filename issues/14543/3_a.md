Since the question came up in the pullreq, I'll repeat what I said there here, to clarify why I suggest the -T related behaviour:

The rationale for requesting "no traceback even on -T" is that we run sphinx as part of our CI jobs. In this setup it is unhelpful for Sphinx to write the traceback to a temp file -- we want it in the CI log; and if users find a sphinx error then we'd like it to be easy for them to cut-and-paste and send us the build log output. That would mean we'd like to pass sphinx -T to get tracebacks on the console. But we don't want the traceback in the log for the normal case of ExtensionError, and we don't want the user to see a traceback for the normal ExtensionError either.

If you don't want -T to suppress the traceback for ExtensionError and ConfigError, then I would like an option that provides the behaviour of "print the full traceback on the console in exactly the set of cases where sphinx would otherwise write it to a temporary file, and not in any case where it doesn't".
