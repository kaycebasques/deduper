> > I would like to be able call a directive that produces the docutils.nodes created when an RST heading is parsed.

I read this as: "Parsing the rST source lines
~~~
.. directive: argument
   :option:

   body
~~~
should give the same document tree fragment as parsing the rST source lines
~~~
argument (or header provided by directive)
---------------------------------------------------------------

body or text provided by directive
~~~

Short answer: it is complicated and may result in invalid doctrees in many cases.

* The rST parser does some bookkeeping when it adds IDs and checks for duplicate IDs (cf. `docutils.nodes.document.note_implicit_target()`)
* The "heading" actually starts a `<section>` element and adds a`<title>` element (see `docutils.parsers.rst.states.RSTState.section()`).
* The [Docutils document model](https://docutils.sourceforge.io/docs/ref/doctree.html) specifies, that [a section must be immediately followed by another section (or end the document)](https://docutils.sourceforge.io/docs/ref/doctree.html#structure-model).

You may consider creating a [Topic](https://docutils.sourceforge.io/docs/ref/rst/directives.html#topic) or [Rubric](https://docutils.sourceforge.io/docs/ref/rst/directives.html#rubric).
