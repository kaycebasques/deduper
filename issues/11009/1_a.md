**Is your feature request related to a problem? Please describe.**
I have a documentation project which aims at deploying doc on different environments. Because of this, some parts of the documentation don't apply depending on the target environment. To keep the different "parameters" which determine whether a page is relevant or not for the context, I use metadata in my markdown files. Unfortunately, I didn't find any built in way to use them to filter sources when building the documentation.

**Describe the solution you'd like**
The ideal would be the possibility to specify a metadata dictionary in the conf.py file, in order to specify which meta should be used for filtering, as well as which values should be "kept" during build.
No metadata on a page -> page always built
At least one accepted value for each filtering meta -> page built
One filtering meta with no accepted value -> page skipped

**Describe alternatives you've considered**
I first looked into the "exclude pattern" feature, but unfortunately it gets quite tedious when you have a lot of filtering criteria, and source file names get really messy.

The second alternative I considered was to implement an extension in order to do this job. However I didn't find the proper way to exclude pages from the build process. No matter which core event I use to try and exclude pages, build always fails elsewhere.

I ended up creating a wrapping script to temporarily copy my source directory, and clean both undesired files and indexes before compiling. Though it would be much cleaner if it was in the build process directly
