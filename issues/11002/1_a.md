(This feature request is based on the assumption that [`container`](https://docutils.sourceforge.io/docs/ref/rst/directives.html#container) objects are mapped to LaTeX environments, as described in the section [Miscellany](https://www.sphinx-doc.org/en/master/latex.html) of the docs).

**Is your feature request related to a problem? Please describe.**
I need to generate a PDF (`.rst` -> `.tex` -> xelatex -> pdf) in which I need to consistently format blocks of text. Those blocks have different sub-components which have their own style. A good way to handle this would be to use [Environments](https://www.overleaf.com/learn/latex/Environments) for which I define a set of [arguments](https://www.overleaf.com/learn/latex/Environments#Defining_environments_which_take_arguments). 

Inside the environment, the argument **1** is formatted in red, argument **2** is normal, followed by a horizontal line, etc. 

I defined an environment in the preamble : 

```
% REQUIREMENT STYLE/FORMAT
\newenvironment{sphinxclasscustomizedrequirement}[5]{
	\rule{15cm}{1pt}\\ 
    \small
	\color{red}
	\uppercase{#1}\\
	\color{black}
	\uppercase{SOURCE=#2}\\
	\uppercase{Allocation=#3}\\
	\uppercase{Safety=#4}\\
}{
\rule{15cm}{1pt}\\
}
```

And I call it in `.rst` using a container

```
.. container:: customizedrequirement

    This is a formatted block

```
**Describe the solution you'd like**
As of now, if I create a `.. container`, it will not take arguments (or at least, not with any syntax that I found). 
```
.. container:: customizedrequirement
    HELLO
    WORLD
    
    This is a formatted block
```

Instead of generating this `.tex`

```
\begin{sphinxuseclass}{customizedrequirement}{HELLO}{WORLD}
\sphinxAtStartPar
This is a formatted block

```
\end{sphinxuseclass}

It does this

```
\begin{sphinxuseclass}{HELLO}
\begin{sphinxuseclass}{WORLD}
\sphinxAtStartPar
This is a formatted block
\end{sphinxuseclass}
\end{sphinxuseclass}
```

I tried using `:arg1:` and `:arg2:` in `.rst` with no luck

I came to the conclusion that `.. containers` simply do not consider arguments). It would be nice if they did. 

**Describe alternatives you've considered**
As a temporary workaround, I patch my generated `.tex` to the format I expect to have. However, Sphinx mangles my argument inputs, by ignoring whitespaces, replacing underscores with dashes, etc. 

It'd really be helpful if Sphinx could allow something like this 
```
.. container:: customizedrequirement
    :arg1: HELLO
    :arg2: WORLD
    
    This is a formatted block
```
Where `arg1` and `arg2` would be passed as-is as environment argument.

**Additional context**
Using Sphinx v5.3.0 with xelatex.
