Looked into this further, since I've seen it happen as well - it's not specific to napoleon, it occurs with the base `:param:` and `:returns:` fields as well (without the intermediate napoleon step).

With something like a `.. versionadded:: 1.0` in the parameter description, it gets parsed into a node like this:
```py
<inline:
  <paragraph: "description here">
  <versionmodified: <paragraph: ...>>
>
```
Without it, it ends up as a simple `<inline: <#text: "description here">>`.
The method description looks similar, although with a `desc_content` instead of an `inline` node.

As far as I can tell, the issue comes down to the fact that both the `inline` node above and the contained `paragraph` are considered [translatable](https://github.com/sphinx-doc/sphinx/blob/318914fff21df82d9a3eb6aabedc51373d3a1d25/sphinx/util/nodes.py#L192), whereas in the method description case, the `desc_content` node isn't translatable, as intended.
The `inline` generated for the param (or any field list item, really) indiscriminately receives a `translatable=True`, which probably isn't correct?
https://github.com/sphinx-doc/sphinx/blob/318914fff21df82d9a3eb6aabedc51373d3a1d25/sphinx/util/docfields.py#L332-L333

I unfortunately don't know enough about sphinx internals to properly fix it myself, but perhaps this can aid someone more knowledgeable.
