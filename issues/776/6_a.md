@shimizukawa I digged a bit around and could find out that changing [this line](https://github.com/sphinx-doc/sphinx/blob/master/sphinx/search/__init__.py#L58) to

```
_word_re = re.compile(r'[\w\.-]+(?u)')
```

already made the search experience a lot better since terms like

```
8.8.8.8
foo.py
re.match
```

will be found. The index was ~50% bigger - which was acceptable for my application. 

---

However, this was just my first attempt, which fits for my application. Of course it has also it's drawbacks since `match` would not being found if not search explicitly for `re.match`. Also others might want to include a `:`, parentheses or whatever or even use the japanese search language which does not support the `_word_re` at all.

What about implementing an option for this, which can be passed via `html_search_options`? I already did that, but found out, that none of the individual sub classes of `SearchLanguage` calls the parent `init()` method, which looks like the perfect place to implement the option.

Would you accept a pull request which implements this option and adds a `super(...).init(options)`  call on top of each languages `init()` method? [Like this](https://github.com/metashock/sphinx/commit/32008fb353822781ce9335e39259e8b99fea71c5)?
