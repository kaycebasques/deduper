**Is your feature request related to a problem? Please describe.**

When running Sphinx with the [-W](https://www.sphinx-doc.org/en/master/man/sphinx-build.html#cmdoption-sphinx-build-W) flag enabled in a complex build environment (where it adds even more complexity to calculate whether a build should run with parallel flags or not), it would be nice to be able to utilize the [suppress_warnings](https://www.sphinx-doc.org/en/master/usage/configuration.html#confval-suppress_warnings) confval when installing an extension that is knowingly not marked `parallel_safe` for read/write. Although, currently serial warnings lack a type/subtype, so that isn't possible.

If the concept has a chance of getting approved, I can (attempt to) make the PR.

**Describe the solution you'd like**

Given that `suppress_warnings` basically lets the user choose the comprise that works best for them, it seems it wouldn't hurt to allow a type/subtype for the [serial warnings](https://github.com/sphinx-doc/sphinx/blob/cd3f2e435000835dd98a11497440bc16a79ec31c/sphinx/application.py#L1279-L1284). I don't know what the most future proof types/substypes are, but I propose the following:

1. `serial.read` and `serial.write` (`type='serial', subtype=typ`) for [L1280](https://github.com/sphinx-doc/sphinx/blob/cd3f2e435000835dd98a11497440bc16a79ec31c/sphinx/application.py#L1280) and [L1284](https://github.com/sphinx-doc/sphinx/blob/cd3f2e435000835dd98a11497440bc16a79ec31c/sphinx/application.py#L1284). I could see the argument for using `parallel` instead of `serial` for the type here.

2. `ext.{extension_name}` (`type='ext', subtype=ext.name`) for [L1279](https://github.com/sphinx-doc/sphinx/blob/cd3f2e435000835dd98a11497440bc16a79ec31c/sphinx/application.py#L1279) and [L1283](https://github.com/sphinx-doc/sphinx/blob/cd3f2e435000835dd98a11497440bc16a79ec31c/sphinx/application.py#L1283). If there are other places that throw warnings using the extension's name, this convention could be used there as well. Being able to supress warnings for an extension that are thrown outside the extension's code seems useful.

Also some notes on the documentation for [suppress_warnings](https://www.sphinx-doc.org/en/master/usage/configuration.html#confval-suppress_warnings):

Would it make since to reference the [logger.warning](https://www.sphinx-doc.org/en/master/extdev/logging.html#sphinx.util.logging.SphinxLoggerAdapter.warning) docs, mentioning that you can also suppress warnings generated by extensions if they take advantage of the `logger.warning` type/subtype keyword arguments ([example extension docs](https://nbsphinx.readthedocs.io/en/latest/usage.html#suppress_warnings)). Or possibly gear the message towards extension writers and say _"Hey, did you know you can also suppress warnings for your extension?"_, either way I think it's a cool feature that is underutilized (and unknown) by extension writers.

**Describe alternatives you've considered**

It's possible to not use the offending extension, switch to serial mode, or drop the `-W` flag where applicable, but the spirit of this solution seems reasonable.
