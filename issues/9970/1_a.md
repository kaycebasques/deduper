### Description

I'm using the `autodoc_preserve_defaults = True` parameter, because I want documentation to show the function definitions the way they are in the code, as this is much more readable in my case. While this option works well for some parameters, it just doesn't work for others.

Example (from [`pypdfium2/_helpers.py`](https://github.com/pypdfium2-team/pypdfium2/blob/main/src/pypdfium2/_helpers.py)):
```python3

def render_page(
        pdf: pdfium.FPDF_DOCUMENT,
        page_index: int = 0,
        *,
        scale: float = 1,
        rotation: int = 0,
        background_colour: int = 0xFFFFFFFF,
        render_annotations: bool = True,
        greyscale: bool = False,
        optimise_mode: OptimiseMode = OptimiseMode.none,
    ) -> Image.Image:
```

With Sphinx v4.3.0+, this yields the following result:
```
pypdfium2._helpers.render_page(pdf: pypdfium2._pypdfium.LP_struct_fpdf_document_t__, page_index: int = 0, *, scale: float = 1, rotation: int = 0, background_colour: int = 0xFFFFFFFF, render_annotations: bool = True, greyscale: bool = False, optimise_mode: pypdfium2._constants.OptimiseMode = OptimiseMode.none)→ PIL.Image.Image
```

While the hexadecimal integer is correctly preserved (fixed with https://github.com/sphinx-doc/sphinx/pull/9799), the `pdf` type `pdfium.FPDF_DOCUMENT` is strangely expanded to `pypdfium2._pypdfium.LP_struct_fpdf_document_t__`, which is confusing and decreases readability.

### How to Reproduce

```
$ git clone https://github.com/pypdfium2-team/pypdfium2.git
$ cd pypdfium2
$ pip install -r docs/requirements.txt
$ cd docs
$ make html
$ xdg-open build/html/support_api.html
```


### Expected behavior

Autodoc should preserve the arguments as written in the code and not expand `FPDF_DOCUMENT` to `LP_struct_fpdf_document_t__`. Same for `FPDF_BOOKMARK`, which unexpectedly becomes `LP_struct_fpdf_bookmark_t__`.
