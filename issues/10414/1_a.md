### Describe the bug

Functions that wrap callable objects are not properly documented as functions (i.e. they are missing a function signature, see screenshots below)

The `FunctionDocumenter.can_document_member` ends up calling this `is_function` precidate:

https://github.com/sphinx-doc/sphinx/blob/ef665d37fa84788c6e0e08c1a1dac6f78be0de3d/sphinx/util/inspect.py#L305-L307

The issue is then that that predicate attempts to "unwrap" the function:

https://github.com/sphinx-doc/sphinx/blob/bd4b19451c9697b3deec687b8e4c893c3916ad81/sphinx/util/inspect.py#L53-L70

This `unwrap_all` does not recognize the case when a function wraps callable objects, and as a result ends up using `DataDocumenter` instead. Among other things, this prevents the function signature from being documented properly. 

### How to Reproduce

Reproducing on the https://github.com/nv-legate/cunumeric repo requires a fairly extensive compiler toolchain including CUDA support. An MRE that illustrates that `isfunction` fail to recognized functions that wrap callable objects (directly analogous to the ones in our case)  is given below:

```
In [1]: from sphinx.util.inspect import isfunction

In [2]: from functools import wraps

In [3]: class Functor:
   ...:     def __call__(self, a, b):
   ...:         print(a, b)
   ...: 

In [4]: def decorator(f):
   ...:     @wraps(f)
   ...:     def wrapper(*args, **kw):
   ...:         return f(*args, **kw)
   ...:     return wrapper
   ...: 

In [5]: f = Functor()

In [6]: wrapped_f = decorator(f)

In [7]: isfunction(wrapped_f)
Out[7]: False
```

### Expected behavior

`FunctionDocumenter` should be selected and used for functions that wrap callable objects. 

It's possible this could be resolved by generalizing `sphinx.util.inspect.isfunction` or alternatively, `FunctionDocumenter.can_document_member` could add additional conditions to pass.
