Currently, the `refwarn` attribute of reference node is set to `True` for citation nodes or to `warn_dangling` depending on its value (most of the time `warn_dangling` is `False`). In particular, without `-n`, the missing references are *not* warned (which is expected) but with `-n`, missing references are always assumed to have `warn_dangling=True`. 

The issue is that if an event handler decides for instance to dynamically suppress the warning (i.e., without using `nitpick_ignore` or `nitpick_ignore_regex` configuration values) by setting `refwarn=False`, this will be ignored by the default `warn-missing-reference` handler. 

In order to minimize the number of changes, I suggest the following logic in nitpicky mode:

- Set the default value of `warn_dangling` to `None` instead of `False`.
- If `refwarn` is `None` in nitpicky mode, assume that `refwarn=True`. Otherwise, assume that `refwarn=False`. 

Since this logic may not be compatible with third-party extensions, I suggest having a configuration value which enables this logic and only mark this feature as "experimental".
