I think there is one additional wrinkle: `sphinx.ext.autosummary` also emits `autodoc-skip-member`, but with different `obj_type` semantics.

In autodoc, `obj_type` identifies the enclosing object whose members are being documented. The current implementation passes `props.obj_type` alongside the unqualified `member_name`:

https://github.com/sphinx-doc/sphinx/blob/581c0860dfedf9628e1b4c0c019e3c36e5e4a74e/sphinx/ext/autodoc/_dynamic/_member_finder.py#L484-L495

Autosummary instead determines `obj_type` from the candidate member:

https://github.com/sphinx-doc/sphinx/blob/581c0860dfedf9628e1b4c0c019e3c36e5e4a74e/sphinx/ext/autosummary/generate.py#L201-L208

The stub-generation path similarly calls `_get_documenter(value, obj)` and passes that result to the event:

https://github.com/sphinx-doc/sphinx/blob/581c0860dfedf9628e1b4c0c019e3c36e5e4a74e/sphinx/ext/autosummary/generate.py#L541-L547

Consequently, a function in a module receives `obj_type='module'` from autodoc but `obj_type='function'` from autosummary. Likewise, a method in a class receives `'class'` from autodoc but `'method'` from autosummary. The `name` argument is unqualified in both cases.

The current behavior is therefore emitter-dependent. I think we also need to document this distinction and correct the current [autosummary docs](https://www.sphinx-doc.org/en/master/usage/extensions/autosummary.html#confval-autosummary_generate) that mention it "Emits `autodoc-skip-member` event as autodoc does.".
