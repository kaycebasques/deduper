### Describe the bug

pyparsing is seeing a regression in how Sphinx 8.2.3 generates its API documentation, compared to the documentation produced by Sphinx 8.1.3 and earlier.



### How to Reproduce

I've created a repo with a ready-to-run reproducer that sets up a minimal project with all of the necessary conditions to trigger the bug. It can be found at https://github.com/ferdnyc/sphinx-alias-bug-repro, and has a README with details about the bug conditions.

To reproduce:
```bash
$ git clone https://github.com/ferdnyc/sphinx-alias-bug-repro
$ cd sphinx-alias-bug-repro/docs
$ make html
```

If run with Sphinx 8.1.3 or earlier installed, the generated API documentation (in `docs/_build/html/api.html`) will show the following:

> _class_ demo.**MyClass**
> Bases: **`object`**
> 
> Ths is my class documentation.
> 
> `a_method`(arg: str = '') → str
> &nbsp;&nbsp;&nbsp;&nbsp;This is the new, non-deprecated name for my method.
> 
> `old_method`(arg: str = '') → str
> &nbsp;&nbsp;&nbsp;&nbsp;This is the documentation for my legacy alias.

Using Sphinx 8.2.3, the documentation will instead be:

> _class_ demo.**MyClass**
> Bases: **`object`**
> 
> Ths is my class documentation.
> 
> `a_method`(arg: str = '') → str
> &nbsp;&nbsp;&nbsp;&nbsp;This is the new, non-deprecated name for my method.
> 
> `old_method`(arg: str = '') → str
> &nbsp;&nbsp;&nbsp;&nbsp;This is the new, non-deprecated name for my method.

### Additional context

The issue arises in the presence of two conditions:

1. The class `MyClass` contains a member that aliases another member, but with its own docstring applied. i.e. `MyClass` contains:
   ```python
   class MyClass:
       def a_method(...):
           """This is the new, non-deprecated name for my method."""

       old_method = a_method
       """This is the documentation for my legacy alias."""
   ```

2. `MyClass` isn't defined where it's documented. The class is defined in `demo/myclass.py`, then imported into `demo/__init__.py` and added to its `__all__` list (so that it's visible to `autodoc` and documented as part of `.. automodule:: demo`).

If `MyClass` is documented as `demo.myclass.MyClass`, Sphinx 8.2.3 generates the same documentation as earlier versions.

But when `demo/__init__.py` contains this:

```python
from demo.myclass import *

__all__ = [
    "MyClass",
]
```

`.. automodule:: demo` under Sphinx 8.2.3 will lose the separate docstring for `demo.MyClass.old_method`, whereas previous versions did not.
