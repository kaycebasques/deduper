If the documented module contains

```
class Foo:
    """Docstring for 'my' class Foo."""

    #: Doc "comment" for class attribute Foo.bar.
    #: It can have multiple lines.
    bar = "1"

    flox = "1.5"   #: Doc "comment" for Foo.flox. One line only.

    baz = "2"
    """Docstring for class attribute Foo.baz."""

    def __init__(self):
        #: Doc comment for "instance" attribute qux.
        self.qux = "3"

        self.spam = "4"
        """Docstring for 'instance' attribute spam."""
```

then the quotes from inside the docstrings are rendered using the secondary pair of quotes suitable for  the language (since 1.6.1, Sphinx uses Docutils smart quotes transform, cf PR #3666 and linked subsequent issues). 

![capture d ecran 2017-06-19 a 11 21 13](https://user-images.githubusercontent.com/2589111/27278497-ddeb0698-54e1-11e7-8f38-c11656500182.png)

This is with stable at 1.6.3+/0b7031 and HTML output.

One observes that the docstrings inner quotes use the suitable inner quotes for the language (here English), but the comments use the outer quotes. This is logical because indeed the docstrings in python module have outer quotes, hence one deduces that perhaps `autodoc` received result of applying smart quotes transform to the full string, inclusive of its outer quotes.

But now the inner ones are printed in HTML or PDF output. Hence a discrepancy with treatment of quotes in comments.
