**Is your feature request related to a problem? Please describe.**
I noticed that autodoc doesn’t include e.g. `__call__` unless I manually tell it to.


**Describe the solution you'd like**
The autodoc rendering of `Protocol`s shouldn’t be configurable as all their members are by definition public. A class inheriting directly from `Protocol` should have all its members visible in the docs.

Since protocols can also inherit from others, maybe it should be possible to not include members that are part of a superprotocol’s members.

**Describe alternatives you've considered**
On top of the above, we could do the full treatment: A `py:protocol` role, a `.. autoprotocol::` directive, a autosummary template, …

In that case of course `py:class` needs some fallback code to be able to link to `Protocol`s that used to be documented as classes.

**Additional context**
Since Python 3.13, there are [`typing.get_protocol_members`](https://docs.python.org/3/library/typing.html#typing.get_protocol_members) and [`typing.is_protocol`](https://docs.python.org/3/library/typing.html#typing.is_protocol).

Combined, it’s pretty easy to retrieve the set of protocol members:

```py
always_include_member = is_protocol(cls) and member_name in get_protocol_members(cls)
```

`sphinx-toolbox` has this as an extension, but it’s incompatible with Sphinx 9: https://sphinx-toolbox.readthedocs.io/en/latest/extensions/more_autodoc/autoprotocol.html
