### Describe the bug

With `Python 3.14.5` and `sphinx v9.1.0`, when `Mapping` or `Callable` are imported in an `if TYPE_CHECKING` block, the rendered type annotations are incorrect when using `sphinx.ext.autodoc`.

Here's some example (incorrectly) rendered output:

```
convert_to_dict(x: Mapping[__annotationlib_name_1__, __annotationlib_name_2__]) → Mapping[__annotationlib_name_3__, __annotationlib_name_4__]

    Parameters:
        x (Mapping[__annotationlib_name_1__, __annotationlib_name_2__])
    Return type:
        Mapping[__annotationlib_name_3__, __annotationlib_name_4__]
```

These `__annotationlib_name_n__` should be the correct types (e.g. `str`) instead.

### How to Reproduce

Minimal Python module that generates this error:

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from collections.abc import Mapping


def convert_to_dict(x: Mapping[str, int]) -> Mapping[str, int]:
    return dict(**x)
```

### Additional context

I think https://github.com/sphinx-doc/sphinx/pull/13946 might be related: from a brief skim, it's intended to enable static type inspection (as in, non-runtime) which should allow stuff imported inside `TYPE_CHECKING` blocks to be used correctly.

But something might be going wrong when inferring more complex/nested types like `Mapping[str, int]` or `Callable[[str], int]`.
