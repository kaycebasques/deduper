## The Problem

`linkcheck_allowed_redirects` currently supports regex pattern matching for redirects, but it does not fully support dynamic backreference substitution when validating redirected URLs.

This makes it difficult to define reusable redirect rules for large sets of similar URLs.

## Example

Configuration:

```python
linkcheck_allowed_redirects = {
    r"https://(.*)\.readthedocs\.io/en/latest/":
    r"https://\1.readthedocs.io/en/stable/"
}
```

URL checked:

```text
https://numpy.readthedocs.io/en/latest/
```

Redirect target:

```text
https://numpy.readthedocs.io/en/stable/
```

Expected behavior:

* The redirect should be treated as allowed/valid.
* `\1` should dynamically resolve to the captured group (`numpy`).

Actual behavior:

* Backreference substitution is not properly resolved during redirect validation.
* In some cases this can produce failed matches or invalid group reference errors.

## Why this is useful

Projects with many similar redirects currently need to define large numbers of explicit redirect mappings instead of one reusable dynamic rule.

Supporting regex backreference substitution would:

* reduce configuration duplication
* simplify large documentation projects
* improve maintainability of `linkcheck_allowed_redirects`

## Possible approach

Internally, redirect validation could use regex substitution logic similar to:

```python
expected = re.sub(pattern, replacement, original_url)
```

before comparing with the actual redirected URL.
