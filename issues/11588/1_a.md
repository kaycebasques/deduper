### Describe the bug

If a [descriptor-typed dataclass field](https://docs.python.org/3/library/dataclasses.html#descriptor-typed-fields) without a default value (item 3 in the screenshot) is used in a class `Foo`, then the field cannot be accessed from the class, only the instance `foo`. Consequently when Sphinx tries to import the field from the class it errors, halting the build.

I would expect that Sphinx can resolve and display descriptor-typed fields by falling back to ``vars(Foo)`` to get the descriptor instance.

<img width="622" alt="CleanShot 2023-08-13 at 23 49 02@2x" src="https://github.com/sphinx-doc/sphinx/assets/8949649/0c299e36-bda2-4a63-87cf-8d8731c3d563">

(It's ``AttributeError: type object 'FLRW' has no attribute 'H0'`` that is relevant).


### How to Reproduce

This arose in https://github.com/astropy/astropy/pull/15168, but a more minimal example is

```python
from dataclasses import dataclass

class DescriptorField:
    def __get__(self, obj, objcls):
        if obj is None:
            # This field has no default value and must be an arg at instantiation.
            raise AttributeError  # THIS IS WHAT SPHINX DISLIKES.
        return obj.bar
    def __set__(self, obj, value):
        obj.bar = value

@dataclass
class Foo:
    bar: DescriptorField = DescriptorField()
```

Then in the `index.rst`:

```
.. autoclass:: Foo
   :show-inheritance:

   .. autosummary::

      ~Foo.bar
```

`getattr(Foo, "bar")` won't work, but `vars(Foo)["bar"]` will.
