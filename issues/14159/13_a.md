One additional manifestation from #14549 is worth tracking here.

Case (b) reproduces the same parser path. The affected `McpClientConfig` inherits Pydantic fields using `default_factory`, so its generated signature contains `<factory>`. Normal signature parsing therefore fails and falls back to `_pseudo_parse_arglist()`.

The fallback then splits a long `system_prompt` string default at every comma. Fragments containing text such as `CRITICAL: SAFETY` and `assumption: "Heading to the front door..."` are interpreted as parameter annotations because they contain colons, producing erroneous cross-reference warnings for the prose.

This confirms that the problem is not limited to commas inside generic annotations or to dataclasses. Once an unparseable default sends a signature through the fallback parser, commas inside any default value can create malformed parameters and cross-references.

Therefore, regression coverage for the fix should include:

- commas inside generic annotations;
- string defaults containing commas and colons;
- Pydantic-generated `<factory>` signatures, or an equivalent dependency-free signature fixture.
