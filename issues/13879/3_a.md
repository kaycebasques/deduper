It's a legitimate bug. Actually, by doing `from importlib.metadata import version`, we create a `version` globals in `conf.py`. However `version` is also a legitimate configuration option. And because of that... we end up trying to use it in intersphinx:

```py
            f.write(
                (
                    '# Sphinx inventory version 2\n'
                    f'# Project: {escape(env.config.project)}\n'
                    f'# Version: {escape(env.config.version)}\n'
                    '# The remainder of this file is compressed using zlib.\n'
                ).encode()
            )
```

Here, the problem is that `env.config.version` is actually `importlib.metadata.version` which is... a function. Thanks for the report.
