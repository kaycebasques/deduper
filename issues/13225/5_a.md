I would actually support this because sometimes the output produced by autodoc does not suit well our needs, though I don't know how to properly implement this yet. We could treat those kind of directives like an `autoclass` directive and traverse the functions that are identified by the regex (informally, `autoclass` works by first autodocing the class itself, and then autodocing each of its methods).

Another issue is that the regular expression might become quite complex. For instance, it would be good if we can also skip some members because they need to have a special doc instead (also, how would we handle the body of such directive? would it be copied to all picked members?)

However, the `cog` alternative may seem a good alternative for generating RST content (and thankfully, RST supports comments using `..`).
