Consider the following toctree:

``` rst
.. toctree::

    introduction
    argument
    conclusion
```

All files introduction.rst, argument.rst and conclusion.rst contain an index entry for the term "test".

The index will look like:

```
test, [1], [2]
```

with three links (one on "test" itself, and one on each number).

**I would expect** that the order of the links correspond to the "normal" flow of the document, that is:
- the link on "test" points to introduction.rst
- the link on "[1]" points to argument.rst
- the link on "[2]" points to conclusion.rst

**What actually happens** is that the first link points to argument.rst, conclusion.rst, introduction.rst, regardless of the order in the toctree. It seems to be the alphabetical order, which I suspect is the order in which the files were parsed.
