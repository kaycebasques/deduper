**Is your feature request related to a problem? Please describe.**

Using sphinx-build 7.1.0

I'm using sphinx-build to build paginated html with the dirhtml builder.  But if I move a source file from one directory to another and rebuild, the old html file (or, I suppose, directory with index.html in it) is left in the old directory.

This means (for me, after rsync with --delete to /var/www/html) that requests for the old URL do not return a 404 but instead return the old page content.  Forever.

**Describe the solution you'd like**

It would be nice if sphinx-build (or, perhaps the dirhtml builder???) had a command line flag (or maybe a configuration directive, I've not thought it through) that deleted everything that sphinx-build does *not* put into the output directory hierarchy.

My feeling is that a command line flag would be better than a configuration directive, so that if you wanted to put stuff into the output directory hierarchy before building, sometimes, you wouldn't need a whole separate
configuration.  But this is also not really thought through.

**Describe alternatives you've considered**

Doing an `rm -rf` on the target directory solves the problem, at the expense of having to rebuild every output file.

A properly constructed `make clean` should also remove the entire target directory, allowing sphinx-build to start from scratch and thereby avoiding the problem of serving out-dated files.  But requiring that`make clean` be run before every deployment seems error prone.

**Additional context**

I find using sphinx-build directly a better fit than relying on the Sphinx Makefiles.  For one thing, I've got my own Makefiles because I've got additional dependencies.  And it just makes upgrading Sphinx easier.

Anyway, I've added the`rm -rf ` to my Makefile and am living with the extra build time.

I believe that just changing the file name, rather than moving a file to a different sub-directory, also exhibits this problem.  But I have not tested this.

I suspect there are many sites with unwanted "old stuff" that remains accessible.  It certainly took me a long time to discover this was going on and I know "old stuff" has been accessible for some time.

Thank you for your time.
